# Отчёт: как уменьшить объём `size-report.html` без ущерба кликам

## 1. Куда уходит объём (замеры текущего файла, 1 441 398 байт)

| Блок | Байт | Доля | Что внутри |
|---|---|---|---|
| Данные `#data` | 1 388 008 | 96.3% | из них `values` — 1 184 785, `approx` — 56 310, meta строк — 57 455 (в т.ч. href — 18 958), `files` — 40 782, `catalog` — 14 480, `now` — 9 200, `last` — 1 574 |
| Программа | 37 727 | 2.6% | комментарии — 17 341 из них |
| CSS | 13 542 | 0.9% | комментарии — 7 672 |
| Словарь `#ui` + оболочка | 2 121 | 0.1% | — |

Всё решает блок данных. Ключевой замер по `values`: **55 071 ячейка-тройка `{raw,min,tok}`, но уникальных троек всего 1 169 (2.1%)** — файл между коммитами либо не меняется вовсе, либо получает новый «снимок» целиком. Между соседними коммитами меняются в среднем ~5 ячеек из 263. Это делает данные сжимаемыми на два порядка без потери информации.

## 2. Главная мера: словарь + события вместо полных значений (−1.29 MB)

Формат:

- `dict` — таблица уникальных троек (1 169 штук, 21 KB);
- `ev` — по каждой строке коммита список пар «файл → id тройки», **изменившихся относительно предыдущей строки**; первая строка несёт начальное состояние.

Проверено на этой сборке: модель **точно без потерь** восстанавливает все 55 071 ячеек (roundtrip-тест на реальных данных прошёл). Размер: `values` 1 185 KB → **~32 KB** (словарь 21 + события 11).

Цена при старте (замерено в Node, на этой же машине):

- разбор JSON: **14.5 мс → 0.74 мс** (в 20 раз меньше);
- разворачивание событий в полный массив `Int32Array(213×263)`: **0.3 мс**, 224 KB памяти.

Влияние на клики — **нулевое или положительное**: путь клика не меняется архитектурно, он по-прежнему читает тройки, но теперь из типизированного массива + словаря (O(1) lookup, лучше кэш-локальность, в куче 55k объектов → 1.2k). Бонус: вместе с `approx` уходит посимвольное сканирование карты приближений на каждую клетку итога (~167k `charAt` за рендер).

## 3. Прочее в данных (−60 KB суммарно)

| Мера | Было | Станет | Комментарий |
|---|---|---|---|
| Выпилить `approx` и `accuracy` | 56 310 + ~150 | 0 | уже решено вами |
| `files` → пары `[путь, индекс категории]`, метка `label` явно только у ~10 исключений (файлы, ушедшие из HEAD) | 40 782 | ~10 000 | 251 из 261 меток восстанавливаются из пути |
| `rows`: href = константа-префикс + полный sha → хранить только полный sha (короткий — это его срез), `when` как минуты от эпохи | 57 455 | ~28 000 | sha сейчас хранится фактически трижды (полный, срез, внутри href) |
| `catalog` → одна `\n`-строка путей + список «правил» | 14 480 | 8 700 | поле `why` почти всегда null |
| `now` → id словаря, `last` → индексы | 10 774 | 1 200 | — |
| `#ui`: убрать `approxCell`, `exact`, `approximate` | 1 446 | ~1 250 | — |

Итоговый блок данных: **1 388 KB → ~85 KB** (замерено на собранном варианте: 96.4 KB, минус ещё ~11 KB за счёт sha/href/when).

## 4. Программа и CSS (−25 KB)

- Убрать комментарии при вклейке: программа 37.7 → **20.4 KB**, CSS 13.5 → **5.9 KB**. Источники остаются читаемыми и проверяемыми линтером — сжимается только артефакт (сборщик и так уже перекраивает текст при вклейке).
- Опционально — полная минификация обеих: esbuild уже зависимость проекта (им считается метрика `min`), новых пакетов не нужно; даст ~13–14 KB JS и ~3 KB CSS. Против этого только философия репозитория «программа страницы = читаемый код движка», но она держится на тестах, которые вы разрешили не считать.
- Попутно: `report.heading` дублирует `title`, `journal: null` — выбросить.

## 5. Опционально поверх: gzip + base64

Уже один gzip текущего JSON даёт 50.8 KB → 67.8 KB в base64; для варианта из п.2–3 — **~43 KB** base64. Распаковка `DecompressionStream('gzip')` на 43 KB — единицы миллисекунд, клики не задевает. Но это плюс асинхронная обвязка и нечитаемый блок данных; при результате ~113 KB без него — оправдано только если нужен размер ниже 100 KB.

## 7. Оговорки

- Порядок словаря (первое появление) детерминирован — свойство неподвижной точки артефакта сохраняется.
- Смена формата — это `schema: 2`: старые записи выбора в localStorage и старые ссылки станут «чужими» (страница уже умеет их вежливо отклонять).
- Короткие подписи/метки, восстанавливаемые из пути, требуют одного исключения в коде для ~10 файлов, ушедших из HEAD.
- Меру из п.2 стоит принимать вместе с инкрементальными итогами из прошлого отчёта: оба опираются на то, что ячейка строки — неизменяемый снимок.
