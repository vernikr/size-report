# 0070 — планы переработки документации и новая папка журнала

**Запрос.** Создать `docs/plans` с правилом имён `yyyy-mm-dd-имя` на первом уровне; завести
папку работы по документации с главным планом и двумя подпланами (комментарии в исходниках;
остальная markdown-документация). Завести `worklog` с подпапкой `archive`, перенести туда
прежний `WORKLOG.md`, новые записи вести как `worklog/NNNN-слаг.md`. Дальше — по одному
посильному куску работы за заход, с остановкой под указание агента mission.

**Сделано.**
- `docs/plans/2026-09-15-docs-rework/` — `plan.md` (общий план: цель, состояние, порядок,
  правила, гейты, открытые вопросы), `comments.md` (подплан по комментариям: правило
  «только то, что нельзя вывести из файла», порядок разбора по `git blame`, 11 воображаемых
  модулей), `markdown.md` (подплан по markdown: актуализировать → сжать → перевести, порядок
  по важности для читателя, таблица сторожей, которые правятся вместе с документом).
- `WORKLOG.md` → `worklog/archive/WORKLOG.md` (`git mv` — байты не тронуты); `worklog/0070-*.md`
  открывает новый журнал, нумерация продолжается с 0071.
- Таблица файлов `README.md` называет `worklog/` и `docs/plans/`; сторож документации
  (`tools/docs-facts.js`) читает прежний журнал по новому пути — иначе проверки ссылок на
  его разделы не нашли бы файл.
- Найдено при разборе и записано в план: сторож ищет таблицу файлов по названию «Что в
  репозитории», таблицу прогонов — по словам «Быстрый»/«Полный», а `§` без имени документа
  относит к `requirements.md` по слову «требовани». Перевод этих документов требует правки
  сторожей **в том же коммите**, иначе документ перестаёт быть проверяемым.

**Предложено.**
- Открытый вопрос плана: после переноса журнала отчёт берёт первым знакомым журналом
  `CHANGELOG.md` (`JOURNALS` в `src/project.js`) — либо принять, либо научить инструмент
  журналу в подпапке (правка инструмента, значит выпуск и подключение копии).
- Второй: выпускать ли PATCH на каждую порцию правки комментариев (байты тарболла меняются,
  поведение — нет).
