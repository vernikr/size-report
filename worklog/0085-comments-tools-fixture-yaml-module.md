# 0085 — комментарии инструментов: фикстура, эталон, YAML (модуль M9c)

**Запрос.** Пройти часть M9c подплана `comments.md` — `tools/make-fixture.js`,
`tools/parity-freeze.js`, `tools/yaml.js` — обычными правилами (датировка, отброс неактуального и
неверного, английский язык, сжатие, поведение и данные не трогаются), отдельно сверить две копии
объяснения про `core.quotePath=false` (в изготовлении фикстуры и в заморозке эталона), учесть
трейлер `Gate-Change:` для гейт-файлов.

**Сделано.** Строк до → после: `tools/make-fixture.js` 249 → 248, `tools/parity-freeze.js`
228 → 226, `tools/yaml.js` 134 → 134; часть 611 → 608. Диффом проверено: изменены только строки
комментариев, ни одной строки кода. Гейт-файлов среди этих трёх нет (`tools/gates/`,
`tools/suites.js`, `test/gates-*`, пороги, базы, `package.json`, workflow, хуки), поэтому трейлер
`Gate-Change:` не требовался — проверено списком гейт-файлов, а не по привычке.

**Сверка про `core.quotePath=false` — как и просили, обе копии про свою копию.** Оба места
ссылались на `harness.FROZEN`, **которого не существует**: замороженную копию проверки берут через
`frozenTarget()` (`tools/harness.js`), а имя `FROZEN` — это локальная переменная в
`test/frozen.test.js`. Обе ссылки теперь называют то, что есть. Само утверждение верно у обоих и
равно окружению `frozenTarget`: `core.quotePath=false`, потому что копия старше закрепления, которое
движок ставит себе сам. Цена ошибки проверена по настройкам фикстуры в том же файле: колонка
`заметки.md` (в файле фикстуры — `docs/заметки.md`) и есть та строка с не-английским именем, которую
машина с умолчаниями git потеряла бы молча.

**Найдено неверное и устаревшее:**

1. `tools/make-fixture.js`: «в фикстуре он обязан остаться неотслеживаемым, а не **восемнадцатым**
   коммитом». Коммитов в фикстуре 16 (замер: `fixtures/synthetic/manifest.json`), значит коммит
   артефакта был бы семнадцатым. Число убрано — правило от него не зависит и больше не устареет.
2. `tools/make-fixture.js` и `tools/parity-freeze.js`: отсылка `REFACTOR.md` R-1.5 (адрес в
   документ, который переписывает эта же работа). Происхождение копии сказано словами и ровно
   так, как его описывает `tools/harness.js`: байты берутся из истории, из того коммита, который
   путь завёл, и сверяются с хешем, записанным происхождением эталона.
3. `tools/yaml.js`: «разборщик один на **оба** сторожа — шаблон проверки для чужого проекта и
   выпуск из CI». Сторожей теперь три: к ним добавился `test/gates-verify.test.js`, который тем же
   разбором читает описание CI (сверено по импортам). Теперь сказано «на каждый сторож, читающий
   описание рабочего процесса».
4. `harness.FROZEN` — см. выше: две ссылки на несуществующее имя.

**Сверено и оставлено.** Случай с выпуском, которым объясняется сам разборщик: рабочий процесс
выпуска падал за 0 с, потому что `? … : …` стоял незакавыченным значением, а прежний сторож искал
подстроки — сверено по архивному журналу (проход 22). Пример потокового списка `tags: ['v*']` —
из `release.yml`, и он там есть. Прочее сверено по коду: манифест не берёт в список сам себя;
артефакт собирается на клоне и остаётся неотслеживаемым; копия запускается трижды (`--json`,
`--write`, контрольный режим); артефакт не берётся из ревизии, а собирается и сверяется с лежащим в
ней; проект-потребитель открывается только на чтение и только на клоне; ревизия и проект по
умолчанию — из манифеста; обрезанность проверяется у клона; разбор идёт тремя шагами с одним
состоянием. Текст сгенерированных записок (README фикстуры и эталона) — данные, не тронут.

**Проверено.** `git diff`: изменены только строки комментариев; кириллицы вне комментариев в диффе
нет; старые формулировки (`harness.FROZEN`, `REFACTOR.md`, «восемнадцатым коммитом», «оба сторожа»)
поиском в этих файлах не находятся; `pnpm run verify:fast` зелёный целиком (5 шагов, 72 проверки из
177).
