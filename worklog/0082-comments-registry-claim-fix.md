# 0082 — устаревшее обоснование про имя в реестре: правка вне модуля

**Запрос.** Закрыть долг, найденный в проходе M8: то же мёртвое обоснование («имени пакета в реестре
здесь быть не может, оно занято чужим пакетом, и установка по имени поставила бы его») стоит ещё в
четырёх местах вне модуля. Правила те же: сверить утверждение с кодом и документацией, английский
язык, краткость, только комментарии; кода и поведения не трогать.

**Сделано.** Пять файлов (четвёртое место — не последнее, см. ниже), строки до → после:
`src/refusal.js` 139 → 137, `src/config.js` 234 → 234, `src/project.js` 296 → 297,
`test/docs-pin.test.js` 63 → 63, `test/docs-commands.test.js` 183 → 183. Диффом проверено: **ни
одной** строки кода не тронуто — правка целиком в комментариях. Кириллица в комментариях трёх
исходников не осталась (в этих файлах её и не было), мест отказа не тронуто, и поиск по дереву
больше не находит прежней формулировки ни в исходниках, ни в проверках.

**Пятое место, найденное при сверке.** Правя четыре названных места, поиском же нашлось пятое —
`test/docs-commands.test.js`, сторож, который требует, чтобы инструкции звали инструмент путём
внутри проекта, а не именем пакета: в его комментарии стояло то же «запускает чужой пакет под тем же
именем». Оно исправлено вместе с остальными, потому что цель — чтобы каждый комментарий говорил
правду, а не чтобы их стало ровно четыре.

**На что заменено (обоснование сверено, а не придумано).** Проверено реестром: область
`@vernikr/size-report` отдаёт 2.4.0 с описанием этого пакета, то есть имя своё; чужим осталось только
необластное `size-report` (1.0.2, посторонний пакет про React). Отсюда верная причина у каждого места:

- зов по имени пакета в проекте без пакета идёт в реестр и запускает **не ту ревизию, чем та, которую
  проект закрепил** (а необластное имя там и вовсе чужое), тогда как путь внутри проекта работает там,
  где пакет установлен, и отказывает на месте там, где его нет, не выходя в сеть;
- ссылка на выпуск у совета об установке берётся потому, что ведёт на **ту самую ревизию, которую
  описывает документация**, а не на то, что реестр отдаёт последним.

**Проверено.** `git diff`: изменены только строки комментариев; `pnpm run verify:fast` зелёный
целиком (5 шагов, 72 проверки из 177). Правок кода и поведения нет — и «данные не тронуты» здесь
доказано тем, что в дифф не попала ни одна строка со знаком «✗» и ни одна строка без пометки
комментария.
