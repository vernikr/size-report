# 0115 — документация: хвост реестра заметок, файл закрыт (M15)

**Запрос.** Пройти остаток `BLOCKERS.md` (записка о слиянии без ключа, N13–N18, ≈160 кириллических строк):
каждую заметку подтвердить кодом или прогоном либо снять как неверную, потом сжать и перевести на английский.
Ключи, которые цитирует поставка, обязаны сохранить номера, порядок ключей не должен разъехаться — доказать
списком до и после. Код логики не трогать, новых сторожей не заводить, чужие правки, предложенные в самих
заметках, не выполнять. `worklog/**` остаётся русским.

**Числа.** 178 добавленных / 186 удалённых = **364 изменённые строки в одном файле** при бюджете 600.
Кириллицы в файле было 169 строк — стало **10**, и все десять названы на месте как цитаты печатаемого вывода
инструмента (два блока воспроизведения B2 и B3, три цитаты движка — `§N5`, фраза отказа B3, путь фикстуры,
и текст внутренней ошибки в N16). Документ закрыт целиком. `verify:fast` зелёный (5 шагов, 72 проверки
из 177), сторожа документации — 8 проверок из 8, гейт-файлов в коммите нет, трейлер не понадобился, выпуска
нет (реестр в тарболл не входит).

**Ключи: замер до и после.** Схема файла не менялась: `## B1.`–`## B3.` остались разделами, записи — пунктами
`- **N#.`, номера идут **N1 … N18** подряд, закрытые N2 и N8, N10 не тронуты. Все ключи, которые называют
документы поставки (`§B1`–`§B3`, `§N2`, `§N4`, `§N8`, `§N10`, `§N13`, `§N16`, `§N17`, плюс `§N11` только в
подплане), сохранили и номер, и смысл: в этом проходе ни один ключ не переносился и не перенумеровывался.

**Записка о слиянии была неверна дважды, и это главная находка прохода.** Замер на git 2.50.1 с хуками,
пишущими строку в журнал вызовов: три обычных коммита дали по три вызова `pre-commit`/`commit-msg`/
`post-commit`, а `--no-ff`-слияние — `pre-merge-commit`, `commit-msg` и `post-merge`, и **ни одного**
`pre-commit`/`post-commit`. То есть утверждение «`pre-commit`/`commit-msg`/`post-commit` не бывает вовсе»
неверно в части `commit-msg`: git проверяет сообщение слияния и зовёт его (и с `-m`, и с редактором —
набор один и тот же). Вторая половина подтвердилась: при живом `MERGE_HEAD` команда `git commit --only <путь>`
падает с кодом 128 и `fatal: cannot do a partial commit during a merge.` — поэтому коммит отчёта собирается
плумбингом. В комментариях самого инструмента (`src/hook.js`), в `test/hook.test.js` и в README сказана только
верная половина («`post-commit` при слиянии не выполняется»), так что переоценка жила ровно в этом реестре.
