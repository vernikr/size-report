## Что оказалось неверным (и теперь сказано прямо)
- **§8.2 планировал переезд как `0.1.0` — такой метки не было:** первый выпуск `1.0.0` 2026-09-14, сегодня пакет
  на **2.4.0**, числа каждого выпуска в `CHANGELOG.md`. Там же: `schema: 1` в данных есть, а `schemaVersion`
  настроек и `--migrate` не появились вовсе (`BLOCKERS.md` §N17); версия необязательной зависимости **доходит**
  до читателя (она в `method`), а обещанное поле `version` датчика и ключ кэша — принадлежность кэша, которого нет.
- **§8.4 описывал непубликованный приватный пакет:** сегодня пакет опубликован и публичен как
  **`@vernikr/size-report`**, выпуски идут тегом из CI по удостоверению (R-4.24); необластное имя занято чужим
  пакетом — перемерено 2026-09-16, `npm view size-report versions` заканчивается на **1.0.2**. Потребитель берёт
  пакет **тегом**, а не коммитом: его манифест читается
  `"size-report": "github:vernikr/size-report#v1.2.0"`. Сценарий с GitHub Packages не понадобился вовсе.
- **§8.5 описывал семь шагов CI:** сегодня это **одна работа** `verify` с `pnpm run verify`, и секретов не
  требует, потому что история потребителя лежит бандлом (`fixtures/live/history.bundle`, 149 коммитов на
  `bd6ef9d`), а профиль отдаёт его `parity:live` ключом `--repo` (`tools/gates/run.js`).
- **§9 утверждал «хук не коммитит»** — того же класса, что ложь §4.9, найденная в M18: хук коммитит отчёт,
  а зацикливание невозможно по устройству (плумбинг не зовёт хуки, а путь отчёта не получает строки). Замок лежит
  в каталоге git (`<git-dir>/size-report/hook.lock`), выключатели — `SIZE_REPORT_NO_HOOK`, `hooks.enabled: false`,
  `uninstall-hook`; чужой `core.hooksPath` отвергается с готовой строкой.
- **§8.1 обещал поля, которых нет:** одного `exports` вместо двух (схема настроек не появилась), шести `files` без
  `dist` (страница — один самодостаточный файл, сборки нет), точных версий необязательных зависимостей вместо
  диапазона, `postinstall` вместо сборки на `prepack`.
