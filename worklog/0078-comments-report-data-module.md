# 0078 — комментарии данных отчёта, производных величин, сборки файла и оформления (модуль M6)

**Запрос.** Пройти модуль M6 подплана `comments.md` — данные отчёта, сводные числа, сборка файла и
оформление: `src/data.js`, `src/derived.js`, `src/artifact.js`, `src/css.js`. Правила те же:
датировка через `git blame`, отброс неактуального и неверного, английский язык, сжатие до того, что
не выводится из кода файла; поведение и данные не трогаются. Предмет сверки, названный отдельно:
соглашение о честности чисел и причина собирать данные страницы и её оформление порознь.

**Сделано.** Строк до → после: `src/data.js` 121 → 115, `src/derived.js` 116 → 112,
`src/artifact.js` 37 → 37, `src/css.js` 28 → 28; модуль 302 → 292. Диффом проверено: ни одной
строки кода не тронуто — правка легла только в комментарии. Кириллицы после прохода в этих файлах
нет вовсе (все четыре — движок; тексты для человека живут в словаре локалей), и в дифф не попала ни
одна строка со знаком «✗».

**Что уточнено против кода (два места, где комментарий описывал мир, которого уже нет):**

- `src/data.js`, блок про производные величины: было «их считает и артефакт (импорт ниже)» — но
  `data.js` не импортирует `src/derived.js` вовсе. Сверено: страница получает этот файл **текстом**
  вклеенным в себя (`pageScript` → `pageSource('../derived.js')`), а из терминальных ответов его
  импортирует `src/modes.js` и таблица страницы. Сказано то, что верно, а прежнее «двум отчётам
  разойтись нечем» осталось в прошлом: отчёт теперь один файл.
- `src/derived.js`, знак минуса в клетке: было «у артефакта он заморожен эталоном побайтово, страница
  ставит типографский» — то есть подразумевалась вторая, HTML-форма отчёта с машинным минусом.
  Проверено поиском: у `cellParts` **ровно один** вызов во всём дереве (страница, передаёт
  типографский знак), второго вывода разметки нет. Сказано то, что верно: знак передаётся вызовом, а
  сам он в списке имён, замороженном проверкой (`test/api.test.js`).
- Там же убрана двойная шапка `src/data.js`: два заголовка подряд говорили одно и то же про
  «абсолютные значения без производных величин» — осталась одна мысль.

**Что сверено с кодом и потому оставлено как верное:**

- Пометка приближения ставится тем же правилом, что и подпись метрики: `approx[m] = !pointExact(...)`
  в `src/history.js` и список приближённых форматов в `src/metrics.js` считаются одной функцией;
  метрика без ни одной пометки в отчёт не попадает вовсе — код это и делает.
- Список пропущенных коммитов страница не несёт **намеренно**: коммит самого отчёта попадает в тот же
  список, и файл перестал бы быть неподвижной точкой (в сборке страницы это `NOT_IN_FILE`). Прежняя
  оговорка «странице он не нужен» была догадкой о причине; теперь названа причина из кода.
- Каталог путей: пустое поле причины — файл измеряется, иначе названа причина (`rule` или `choice`) —
  совпадает с тем, как страница читает этот знак.
- Проверка сверяется с теми же байтами, что пишутся: `checkMode` берёт их у `artifact()`, а не собирает
  свою форму.
- Два требования к `src/derived.js` (ни импортов и ни состояния модуля, экспорт объявлением и один
  `import` на строку) — это ровно то, что умеет вклейка: `stripModules` построчно снимает
  `import …;` и заменяет `export function` на `function`.
- Оформление: соглашение о цвете дельт действительно задано один раз (`src/table.css`, `.up` зелёный,
  `.down` красный), а `src/page/app.css` его не трогает — проверено поиском по обоим файлам.

**Проверено.** `git diff`: изменены только строки комментариев; `pnpm run verify:fast` зелёный
целиком (5 шагов, 72 проверки из 177).

**Предложено.** Следующий по подплану — M7 «страница» (`src/page/app.js`, `build.js`, `dom.js`,
`panel.js`, `state.js`, `table.js`, `app.css`, `src/table.css`; 940 строк, два захода). Там предмет
