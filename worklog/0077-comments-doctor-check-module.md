# 0077 — комментарии диагностики, полноты покрытия и объяснения строки (модуль M5b)

**Запрос.** Пройти вторую половину модуля M5 подплана `comments.md` — диагностика, полнота покрытия
и объяснение пропущенной строки: `src/doctor.js`, `src/check.js`, `src/explain.js`. Правила те же:
датировка через `git blame`, отброс неактуального и неверного, английский язык, сжатие до того, что
не выводится из кода файла; поведение и данные не трогаются. Отдельно сказано: правила «что
считается находкой» и порядок важности ответов сохранять только в том виде, который верен
текущему коду.

**Сделано.** Строк до → после: `src/doctor.js` 281 → 277, `src/check.js` 140 → 137,
`src/explain.js` 130 → 130; половина модуля 551 → 544, модуль M5 целиком 1165 → 1148. Диффом
проверено: **ни одной** строки кода не тронуто — правка легла только в комментарии (в этой половине
даже концевых комментариев на строках с кодом не было). Кириллица осталась только в текстах
сообщений (12 + 24 + 33 строки — это данные: подписи причин, итогов хука и тексты для человека), и в
дифф не попала ни одна строка со знаком «✗».

**Что сверено с кодом и потому оставлено как верное:**

- Порядок истории от старых к новым: `readHistory` действительно читает `git log --reverse`,
  значит «коммит, заведший путь, — первый» верно и по-прежнему не выводится из кода самого файла.
- Причины «нет строки» — ровно три (`merge`, `report`, `flat`), и они приходят из двигателя
  (`src/history.js`), а «мимо колонок» — это уточнение поверх `flat`, которое делает объяснение:
  именно оно и есть смысл модуля. Улики берутся из того же списка изменённых путей коммита.
- Вес обстоятельств в диагностике один на модуль: ключи `WEIGHT` идут по важности, код выхода
  берётся у самого важного найденного, а не у последнего; `ok` — это полное покрытие и ни одной
  находки-действия; хук в весах не участвует (отчёт собирается и без него).
- Зависимости спрашиваются теми же загрузчиками, что у датчиков, и грузятся только по спросу;
  «не спрашивается» названо наблюдением, а не незнанием.
- Ссылки на проверки живые: `test/environment.test.js` (закрепления чтения git) и
  `test/tokens.test.js` (ленивая загрузка словаря) — оба файла есть, поэтому ссылки оставлены.

**Что отброшено:** номер раздела требований в правиле полноты («§4.2»). Проверено — раздел есть
и называется «Гарантия полноты (обязательное правило)», то есть ссылка была точной, но нумерация
разделов уедет при переработке markdown-документации, а само правило сказано тут же словами;
обещание, которое вот-вот сломается, в комментарии не нужно (то же решение, что для ссылок на
разделы планов в предыдущих проходах).

**Проверено.** `git diff`: изменены только строки комментариев; `pnpm run verify:fast` зелёный
целиком (5 шагов, 72 проверки из 177).

**Предложено.** Модуль M5 закрыт целиком (M5a + M5b). Следующий по подплану — M6 «данные отчёта»
(`src/data.js`, `src/derived.js`, `src/artifact.js`, `src/css.js`, 302 строки, один заход). Там
предмет сверки — соглашение о честности чисел (подпись метрики и приближение) и то, почему
данные страницы и её оформление собираются порознь.
