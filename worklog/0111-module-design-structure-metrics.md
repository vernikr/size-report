**Десять утверждений переписаны по коду и замерам.**

1. **§4, дерево модуля.** Подпакетов нет, и выдуманных папок тоже: `config/`, `git/`, `inventory/`,
   `metrics/`, `measure/`, `model/`, `render/` и `config/schema.json` в дереве отсутствуют. Реально —
   плоский `src/` с двумя швами (`strip/`, `page/`), `bin/` (включая установку хука), `templates/` из трёх
   файлов и `test/` репозитория модуля. Перечень файлов дан по ролям.
2. **§4, принцип границ.** Ядро не знает проекта и читает git через один модуль с закреплёнными настройками
   (`src/git.js`) — закрепление, а не подстановка источника, и делает число одинаковым на разных машинах.
   Идея «источник истории как параметр» кодом не стала: скорость проверкам даёт настоящий репозиторий,
   собранный во временном каталоге (`tools/synthetic/`, `fixtures/`). В `BLOCKERS.md` не пишу: обещание было
   внутренним проектным, а цель — быстрые проверки — достигнута другим способом.
3. **§5.1.** Названы настоящие правила исключения: сам отчёт, блокировки зависимостей, сборка, неизвестное
   расширение и порог размера (512 КБ — страж против сгенерированного), и то, что у каждого пути вне отчёта
   в каталоге стоит причина. Добавлено, что без файла настроек профиль выводится из проекта.
4. **§5.2.** Категории — четыре фиксированных имени (`code`, `docs`, `chore`, `assets`) с настоящей таблицей
   расширений (`CATEGORY_EXTS`), а не «набор настраивается»; колонка может назвать категорию сама
   (`categoryBy: "config"`), и тогда таблица не спрашивается; неизвестное расширение — `code`.
5. **§6, форма данных — переписан целиком, потому что прежняя была выдумана.** В коде нет ни `toolVersion`,
   ни `commits[]`, ни `series[]` с «точками изменения». Реальный контракт снят живым прогоном `--data`:
   `schema`, `tool{name,version}`, `report{locale,title,heading,artifact,fixCommand,journal,showSha}`,
   `metrics[{key,label,note,method,accuracy}]`, `categories[{key,label}]`,
   `files[{label,path,paths,category,categoryBy}]`, `catalog[{path,why}]`,
   `rows[{sha,when,subject,section,href,values[{<метрика>: число}]}]`, `now`, `last`, `approx`, `skipped`.
   «Компактной формы» тоже нет: замер на репозитории с двумя колонками и тремя коммитами показал абсолютные
   значения по всем колонкам в каждой строке.
6. **§6, `approx`.** Это битовая строка по клеткам: замер дал `{"min":{"rows":"111111","now":"11"}}` на
   трёх строках и двух колонках, то есть точность помечается по клетке, а не только по колонке.
7. **§7.1.** Поля «версия алгоритма» у датчика нет; версия инструмента живёт в строке `method` (esbuild,
   токенизатор) — там же, где читатель её и видит.
8. **§7.3, минификатор.** «Вызов как библиотека в одном процессе без внешних команд» — через JS API
   (`transformSync`, `minify: true`, UTF-8, без legal comments), один служебный процесс на прогон.
   Загрузчики — `js`, `ts`, `css`, поэтому «умеет CSS и JSON» верно только для CSS, а **минификатора
   разметки нет**: HTML идёт упрощением и помечается приближением.
9. **§7.3, зависимости.** esbuild и токенизаторы — **необязательные** зависимости пакета: без них счёт
   откатывается на упрощение, а потеря датчика сообщается кодом 4, то есть приближение не едет молча.
10. **§7.4, токены.** Семейство одно — `openai` (`gpt-tokenizer`, кодировки `o200k_base` / `cl100k_base`);
    таблица трёх вендоров заменена на реальность: точный словарь, оценка по длине (≈3 знака на токен — по
    замерам самого этого репозитория; для латиницы завышает) и бинарные форматы по байтам, и обе оценки
    помечены приближением. Переключателя семейств на странице нет: семейство выбирается настройкой, а счёт
    идёт на сборке.
