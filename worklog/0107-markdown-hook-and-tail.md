# 0107 — документация: хук и хвост инструкции в README (M8)

**Запрос.** Пройти шаги 6–8 раздела подключения (хук, ловушки этой же инструкции, уже лежащая копия,
≈100 русских строк): актуализировать по коду и замеру, сжать, перевести; читателя сторожа — тем же
коммитом; цитаты вывода инструмента называть явно; код логики не трогать.

**Числа.** README 990 → 986 строк, кириллицы 106 → **4**, дифф 198 изменённых строк в одном файле при
бюджете 600. Все четыре оставшиеся кириллические строки — цитаты вывода инструмента (предупреждение о
таблице, реестр причин отказа, подпись коммита хука), и у каждой это сказано словами на месте. Правок
читателей сторожа не потребовалось: они читают этот текст только по путям, зовам и именам разделов.

**Два утверждения были неверны, и оба проверены замером, а не рассуждением.**

1. **«Новый файл-колонка должен быть закоммичен, иначе проверка скажет „не совпало с деревом
   коммита“».** Опыт в отдельном репозитории: конфиг закоммичен, новый файл-колонка не отслеживается —
   прогон **зелёный** (код 0), колонка просто остаётся без чисел. А названное сообщение принадлежит
   другой проверке: она ловит состояние, потерянное при переносе между коммитами (класс `BLOCKERS.md`
   B3, слияние без пути в списке изменённых). Совет («сначала `git add` + коммит») остался, названное
   следствие исправлено: молча пропадают не строки, а числа.
2. **Отказу минификатора снова приписали «два выхода»** — это четвёртая копия той же неправды, которую я
   чинил на проходе M4b. По коду выход один (`minify.ext`: способ `strip` передал бы тот же файл гарду, и
   вердикт был бы тот же), а два выхода есть у отказа самого гарда (убрать расширение из `minify.guard`
   или задать `minify.ext`). Теперь ловушка их различает.

**Снимки заменены адресами.** Времена разбора модуля (0,1 мс; поток ≈54 мс против `node --check` ≈86 мс
на клетку) ушли: их место — `REFACTOR.md` R-5.4, где они записаны с датами и условиями замера. Там же
ушла заявка «цели по времени проверяются машинно»: не проверяются, потому что целей нет вовсе — так
сказано в `tools/suites.js`; вместо неё назван настоящий список того, что держит сторож. Из чисел
миграции `safe-resets` осталось то, что держит замороженный эталон (225 673 Б, sha256 `1bdb27e1…`,
95 × 27 — `fixtures/parity/manifest.json`), а «91 × 25» после удаления копии убрано: это снимок чужого
проекта, которого ничто не держит.

**Что перемерял живьём.**

- **Слияние не зовёт `post-commit`.** Опыт на git 2.50.1: три обычных коммита дали три `post-commit`, а
  слияние — только `post-merge`, без лишнего `post-commit`. Поэтому в тексте теперь сказано, зачем нужен
  второй файл хука, и сказано, что это проверено на git 2.50.
- **Минификатор выключен, а отчёт собран с ним** (`SIZE_REPORT_NO_OPTIONAL=1`): проверка отвечает
  **кодом 1** про расхождение с историей и тут же печатает заметки о другом счёте с готовой починкой —
  ровно то, что обещает текст; сборка в том же окружении отдаёт код 4.
- **Незакоммиченная правка не двигает таблицу**: правка колонки на диске без коммита оставляет проверку
  зелёной, а коммит трогает строку — и тогда проверка называет расхождение и номер строки.

**Что подтвердил по коду.** Хуки ставятся сами (скрипт установки плюс первый запуск, с оговоркой про
pnpm 10 и `onlyBuiltDependencies`), живут в `.git`, коммитят только путь отчёта (дерево берётся из HEAD с
одной подменённой записью), первый отчёт не коммитят (файл без отслеживания — словами, без коммита),
зацикливание невозможно по устройству (`commit-tree` хуков не зовёт, отчёт строки не получает, есть
замок), отказ инструмента коммит не роняет и остаётся для `doctor`, выключателей два (`hooks.enabled` и
`uninstall-hook`), а у окружения есть свой рычаг `SIZE_REPORT_NO_HOOK` — он в текст добавлен, потому что в
тексте про два способа читатель искал бы его там же.

**Проверено.** `pnpm run verify:fast` зелёный (5 шагов, 72 проверки из 177). Полный профиль — перед
коммитом (в нём `pack:check` сверяет шаблоны, а этот проход их не трогал).

**Предложено.** Следующая часть — **M9**: `templates/README.md` и две рукописные заметки фикстур (113
русских строк, 3 файла). Читатель у этой части один — `test/templates.test.js`: он требует, чтобы записка
называла свои два файла и `AGENTS.md` (по языку не зависит), поэтому переводится без правки сторожа.
`fixtures/synthetic/README.md` остаётся вне области: его пишет изготовитель фикстуры, и полная сверка
эталонов сравнивает его байт в байт.
