# 0109 — документация: требования к продукту (M10)

**Запрос.** Пройти `docs/requirements.md` (115 русских строк): актуализировать по коду и замеру, сжать,
перевести; нумерация разделов переписывается вместе с телом, потому что на неё ссылаются другие документы;
перед правкой замерить, кто ссылается, после — проверить, что входящие ссылки ведут в существующие
разделы; код логики не трогать.

**Числа.** 118 добавленных / 115 удалённых = **233 изменённых строки в одном файле** при бюджете 600;
кириллицы в файле не осталось (ни одной строки), множитель на прозе ≈2,0 — как предсказывала нарезка.

**Кто ссылается — замерено до правки, проверено после.** Входящие ссылки нашлись только в двух файлах:
`PLAN.md` (§3.1, §6.1, §7.1, §12, §4.3, §11.2, §7.3, §4.2 дважды, §6.2 + §11.6 одной строкой, §3.3,
§7.2, §8 + §12 одной строкой, §3 и §4 в перечне документов) и `REFACTOR.md` (§4.2). Разделов с
нумерацией 1–14 и подразделами я не тронул ни одного, поэтому все ссылки ведут туда же, где вели:
сторожа документации (`node --test` по четырём файлам, включая проверку «ссылки ведут в существующие
разделы») зелёные, 7 из 7. Ссылок на пункты внутри разделов (вроде §3.1.1) нет ни одной, а §13 и §14 не
названы нигде — там я и менял форму.

**Одна ссылка была битой и починена.** §3.2 отправлял за сжатым размером в «раздел 8», а §8 — про то,
показывать или ограничивать; gzip живёт в §12. Теперь сказано §12.

**Семь утверждений были неверны или устарели — каждое проверено кодом или живым прогоном.**

1. **«Сжатый размер в первой версии не считаем»** — он в реестре (`src/metrics.js`, zlib, уровень 9) и
   считается по настройке. Замер: отдельный проект с `metrics: ["raw","min","gzip"]` собрался зелёно, а
   слой данных страницы назвал gzip с методом «zlib, уровень 9» и точностью `exact`. Строка §12 «вне
   рамок» осталась, но теперь говорит правду: в наборе первой версии его нет, а в реестре он есть — это
   ровно то, на что ссылается `PLAN.md` («`gzip` в реестре метрик»).
2. **«Три метрики обязательны»** — обязательны, но набор по умолчанию `["raw","min"]` (`DEFAULT_CONFIG`),
   а `tok` включается настройкой: его словарь — необязательная зависимость (`optionalDependencies`:
   `esbuild`, `gpt-tokenizer`). Сказано это, а не «все три всегда».
3. **«Минус балласт — это настоящая минификация»** — движков два (`MINIFY_ENGINES`): снятие балласта
   (по умолчанию, и это не минификация: имена не сокращаются) и настоящая минификация esbuild,
   включаемая настройкой по расширениям, с откатом на упрощение для остальных форматов.
4. **Метрика токенов** — точна со словарём, без словаря это оценка по длине, помеченная приближением,
   бинарные форматы считаются байтами (`src/tokens.js`). Обещание честности (§3.3) сохранено.
5. **«Отчёт исключается из контроля версий по умолчанию»** — не так: инструмент не кладёт отчёт ни в один
   коммит и не правит список игнорирования (`--init` тоже), а отслеживается файл или нет — решение
   проекта. Следствие названо в обоих состояниях (`storeReport` в `src/hook.js`): без отслеживания
   пересборка история не трогает, с отслеживанием хук коммитит отчёт **отдельным коммитом**.
6. **Защита от зацикливания** была описана как «элементарная защита, например ограничить глубину» — по
   коду это устройство, а не флаг: коммит отчёта собирается сантехникой git (`commit-tree`), которая
   хуков не зовёт вовсе, а путь отчёта не получает строки, поэтому та же пересборка даёт те же байты; и
   есть замок на два одновременных хука.
7. **«Обрезанная история — достроить отчёт по доступным данным с пометкой»** — этого не происходит:
   `assertFullHistory` отказывает кодом 3 и называет починку (`git fetch --unshallow`, `fetch-depth: 0` в
   CI). Оставлена вторая ветка требования — понятная инструкция.

**Хуки проверены живым прогоном.** В том же отдельном проекте первый же запуск сборки напечатал «хук
поставлен: .git/hooks/post-commit, .git/hooks/post-merge» — обещание §7.1 («ставятся сами при первом
запуске в проекте») верно. Заодно в §7.3 названы все рычаги, которые есть в коде: `hooks.enabled`,
`SIZE_REPORT_NO_HOOK`, `uninstall-hook` и `size doctor` как отчёт о том, что автоматика делает.

**§14 переписан с «неразрешённых мелочей» на решённые вопросы.** Все четыре вопроса закрыты, и каждый
теперь называет, где живёт ответ: путь отчёта выводится из проекта (`docs/size-report.html`), данные для
агента — это слой контракта, на котором построена сама страница (`--data`), минификатор выбирается
настройкой по расширению, а пометка о способе стоит рядом с числом, а не отдельно. Ни один документ §14 не
называет, поэтому входящих ссылок эта переделка не трогала.

**Проверено.** `pnpm run verify:fast` зелёный (5 шагов, 72 проверки из 177). Полный профиль не нужен: гейт-файлы
не тронуты, тарболл этим проходом не менялся.
