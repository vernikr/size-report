# 0086 — журнал отчёта после переезда: решение вместо открытого вопроса

**Запрос.** Разобрать до конца случай с журналом отчёта (после переезда `WORKLOG.md` в
`worklog/archive/` отчёт выбрал журналом `CHANGELOG.md`), сначала выяснив, лечится ли он без
правки логики; код логики не трогать ни при каком исходе, а если единственный путь — правка
логики, записать находку, доказательство, варианты с ценой и вопрос для пользователя в
`BLOCKERS.md`, оставив указатели в плане и журнале.

**Механизм (проверено по коду, а не по памяти).** Настройки, выведенные из проекта, ищут журнал
среди четырёх имён (`src/project.js`: `JOURNALS` = `WORKLOG.md`, `CHANGELOG.md`, `CHANGES.md`,
`HISTORY.md`) и берут первое существующее — и только в **корне** (`exists()` склеивает корень с
именем). Файл из подкаталога или каталог записей вывод назвать не может. Явный журнал настройками
инструмент поддерживает, но `size-table.config.json` неполным быть не может: отсутствие файла и
есть «настройки выводятся из проекта», а файл без колонок отказ проверки настроек отвергает.

**Что измерено в собранном отчёте.** 113 строк, раздел несут 14: 13 заведены релизными коммитами
(случай «заведён новый», от порядка документа не зависит) и одна — коммитом `8321e65`, который
правил существующий раздел `1.0.0`. Сверено с самим коммитом: он тронул **только** этот раздел
(правка в строках 124+ `CHANGELOG.md`), то есть и здесь имя верное. Якоря живые: например
`CHANGELOG.md#240--2026-09-15` ведёт на настоящий заголовок. Итог: сегодня ни одна из 14 ссылок не
врёт.

**Решение: принять и записать словами.** Инструмент и его поведение не тронуты ни одной строкой.
Довод не только в цене: выбранный журнал **растёт** — каждый выпуск заводит в нём раздел, — тогда
как архивный журнал заморожен на разделе 73 и оставил бы без раздела всё, что было после переезда
(в том числе весь этот проход). Записанное соглашение: журнал отчёта этого репозитория —
`CHANGELOG.md`, то есть строки считаются по выпускам, а не по проходам рабочего журнала.

**Что записано куда.** `BLOCKERS.md`, заметка N11 — находка, доказательство замером, принятая цена
(два следствия: пропала привязка к проходам и стало достижимо ограничение `touchedSection` — при
правке **двух** существующих разделов отступление назовёт старший, потому что список выпусков
написан сверху вниз) и три варианта с ценой: принять (выбрано), закрепить журнал настройками
проекта (профиль придётся нести руками, каждый новый путь — колонка или запись `skip`, иначе
`check` отвечает кодом 1), научить инструмент журналу вне корня (правка кода плюс решение о
контракте отчёта: `journal.path` перестал бы быть одним путём — новая возможность со своим
выпуском). Вопрос пользователю назван там же. В `plan.md` открытый вопрос заменён решённым, с
числами и указателем на N11.

**Своя ошибка, найденная этим разбором.** В `worklog/0075` (проход M4) было записано, что архивный
журнал идёт «1 → 78». Измерено сейчас по заголовкам: последний раздел архива — 73. Запись
исправлена: журнал — не место для красивого числа, а ошибка в нём читается как факт.

**Проверено.** Изменены только `BLOCKERS.md`, план и две записи журнала — исходного кода в диффе
нет. `pnpm run verify:fast` зелёный целиком (5 шагов, 72 проверки из 177); отдельно прогнаны три
сторожа документации (7 проверок) — зелёные, то есть новые пути и ссылки раздела в заметке
существуют и ведут куда сказано.

**Предложено.** Вернуться к подплану комментариев: следующая часть — M9d
(`tools/parity-live.js`, `tools/pack-check.js`).
