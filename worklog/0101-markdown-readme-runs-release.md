# 0101 — документация: остаток README о прогонах, проверках и выпуске

**Запрос.** Закончить README до абзаца о странице отчёта: таблица прогонов, числа проверок в прозе,
абзацы о непрерывной проверке и выпуске, с правкой читателя таблицы в том же коммите. Границу задаёт
бюджет коммита, а не число частей нарезки; соседние мелкие части можно брать вместе.

**Две ложные посылки вычищены, и обе про устройство ворот.**

1. **«CI зовёт полный прогон дважды: обычной средой и без настроек машины»** — неверно. В
   `.github/workflows/ci.yml` одна работа и **один** шаг: `pnpm run verify`. Прогон без настроек git
   живёт не в полном профиле, а в slow (проверено по `tools/gates/run.js`: `FULL` — восемь шагов
   `lint:strict`, `metrics`, `dup`, `deps`, `test:all`, `parity:live`, `check:standards`, `pack:check`,
   а `test:all` с `GIT_CONFIG_GLOBAL=/dev/null` и `cover` добавлены только в `slow`; расписание —
   `.github/workflows/verify-slow.yml`, понедельник 04:17 UTC). Ту же ложь я сам перевёл в `AGENTS.md`
   на проходе M1 — она там была в русском тексте. Починено в обоих файлах: теперь названо то, где шаг
   на самом деле.
2. **Выпуск обещал не то, что делает работа.** В `release.yml` нет полного профиля: там строгий
   линтер, весь набор и работа из тарболла, сверка версии манифеста с тегом и публикация. И ещё: «явный
   адрес живёт в `publishConfig`» — в манифесте `publishConfig` держит только `access: public`, адрес
   реестра умолчательный, и именно поэтому `registry-url` у `setup-node` не нужен. Существо ловушки
   осталось, довод исправлен. Та же фраза про `publishConfig` стоит комментарием в самом `release.yml`
   — файл гейт-овый и в область этого подплана (markdown) не входит, поэтому не тронут; отмечено в
   подплане как находка для будущей работы по комментариям в YAML.

**Снимки, которые стареют, заменены правилом.** «Выпуск `1.2.0` прошёл именно так: `v1.2.0` → 44 с»
и пример черновой версии «`1.2.0` → `1.2.1-draft.0`» — числа одного выпуска; осталось правило (версию
поднимает человек в манифесте и `CHANGELOG.md`, а работа только сверяет её с тегом; черновой номер
берётся выше манифестного, чтобы реестр не отказал). Два абзаца истории о дефектах, найденных первыми
прогонами CI, сжаты в один и говорят правилами: вывод процессов собирает обвязка, а не склейка строки
(разорванный между кусками чтения многобайтовый символ), и побайтово сверяется только то, что пишем мы
сами — бандл истории упакован git и потому сверяется содержимым, а нести он обязан `HEAD` и ветку
`main` на ревизии эталона. Оба правила подтверждены кодом: `tools/run-tests.js` (сбор вывода),
`tools/check-standards.js` (`bundleFacts`, сравнение по полям, требование `HEAD`+`main`, печать отказа
целиком, а не первой строкой). Адреса `WORKLOG.md` §21/§22 сняты: в корне такого файла нет с переезда
журнала.

**Читатель таблицы прогонов поправлен в том же коммите — и заодно перестал зависеть от формулировок.**
`tools/docs-facts.js` `publishedRuns` ловил строки таблицы по первым словам «Быстрый»/«Полный», то есть
перевод подписи ломал сторож. Теперь строка узнаётся по **ячейке команды** (`pnpm test` против
`pnpm test:all`), а слова подписи — дело документа. Это то же правило, что и в остальных сторожах: они
читают форму, которую держит код, а не перевод.

**Проверено.** `tools/gates/run.js` (профили, включая `test:all:hermetic` только в slow), `ci.yml`
(один шаг, Node 22, действия по SHA, ветка `main` для взгляда на дубли), `verify-slow.yml` (расписание),
`release.yml` (шаги, сверка тега с манифестом, `next` для prerelease, черновой прогон и его слепое
место), `tools/check-standards.js`, `tools/run-tests.js`. `pnpm run verify:fast` зелёный (5 шагов, 72
проверки из 177), полный профиль — зелёный целиком (8 шагов, 59,5 с). Гейт-файлов в коммите нет (правка
`tools/docs-facts.js` — не гейт; сверено списком `GATE_FILES`), трейлер не нужен.

**Числа.** README 1060 → 1050 строк, кириллицы 771 → 711: ушло 60 русских строк, в правленом диапазоне
(148–225) кириллицы не осталось. Дифф: `README.md` 54/64, `AGENTS.md` 4/4, `tools/docs-facts.js` 6/5 —
**137 изменённых строк в трёх файлах** при бюджете 600. Множитель подтверждается: 60 русских строк дали
126 изменённых в README (≈2.1).

**Предложено.** Следующая часть — **M4**: остаток «Статуса» (страница отчёта, память и складывание,
поведение в окне), 190 русских строк. Её нельзя пройти только по коду: там числа настоящего Chrome
(«0,6 мс в обработчике против 107 + 380 мс перекладки», «1060 × 735», «148 подписей»), поэтому либо
перемерить их обвязкой страницы (`tools/page-harness.js`), либо заменить правилом там, где число ничего
не решает. Отдельно на M5 оставлена подозрительная фраза в разделе о замороженной копии: «проверено
тремя прогонами … и прогон без настроек машины — тоже» — это заявка на замер, которого сегодня никто не
повторяет воротами.
