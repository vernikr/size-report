# 0075 — комментарии границы git, истории и журнала (модуль M4)

**Запрос.** Пройти модуль M4 подплана `comments.md` — «история»: `src/git.js`, `src/history.js`,
`src/journal.js`. Правила те же: датировка через `git blame`, отброс неактуального и неверного,
английский язык, сжатие до того, что не выводится из кода. Отдельно сказано: объяснения
закреплённых настроек чтения git, причин брать размеры из объектов и правил разбора журнала
сохранить **только в том виде, который верен текущему коду**.

**Сделано.** Строк до → после: `src/git.js` 221 → 216, `src/history.js` 238 → 235,
`src/journal.js` 66 → 68; модуль 525 → 519, правка — 292 строки в 3 файлах. Диффом проверено:
изменены только строки комментариев, а восемь строк кода тронуты лишь в конце — там правился
сам комментарий (константы и `return` остались байт в байт).

**Что найдено неверным:**

- `src/journal.js`, правило «к какому разделу относится коммит»: было сказано, что «журналы
  ведутся по возрастанию, так что правка почти всегда касается хвоста». Это **неверно для
  журнала, написанного сверху вниз**, а `CHANGELOG.md` — именно такой, и он теперь и есть
  журнал этого репозитория. Проверено: разделы `CHANGELOG.md` идут 2.4.0 → 1.0.0, а `WORKLOG.md`
  (архив) — 1 → 73. Теперь в комментарии сказано то, что верно: случай «заведён новый раздел»
  от порядка не зависит, а отступление к «последнему правленому» в нисходящем журнале назовёт
  самый старый из правленых разделов, а не самый новый. Практическая цена мала (правка старого
  раздела в релизном коммите не делается), но из кода этого не видно, и вранья в комментарии
  оставаться не должно.

**Что проверено против кода и потому сохранено:**

- `src/git.js`: причина закрепления настроек (без `core.quotePath=false` не-английские пути
  приходят закавыченными и колонка не находит файла), цена закреплённой локали (сообщения git
  по-английски, сообщения инструмента — как есть), причина читать блобы пачкой и брать размер
  объекта дешевле содержимого.
- Там же: утверждение, что `env` у `gitTry` нужен хуку для отдельного индекса, сверено с
  `src/hook.js` — там действительно три зова с `GIT_INDEX_FILE` (`read-tree`, `update-index`,
  `write-tree`). Утверждение верно, оставлено.
- `src/history.js`: почему строка даётся по числам, а не по списку файлов; почему берётся тот
  псевдоним колонки, который в коммите есть; почему знак «какие колонки тронул последний коммит»
  пропускает коммиты самого отчёта (иначе отчёт перестал бы быть неподвижной точкой); почему
  сверка с диском идёт по хешам, а не по размерам.

**Проверено.** `git diff`: изменены только строки комментариев; `pnpm run verify:fast` зелёный
целиком (5 шагов, 72 проверки из 177); два места отказа в `src/history.js` и знаков «✗» в модуле
нет — как и было (`test/refusals-catalog.test.js`).

**Предложено.** Дальше по подплану — M5 «проект»: `src/project.js`, `src/config.js`,
`src/init.js`, `src/doctor.js`, `src/check.js`, `src/explain.js` (1165 строк, два захода). Там
живёт самое расхожее объяснение — почему колонкой идёт каждый файл и почему первый запуск
обязан быть полным; оно и будет сверяться с кодом. Открытый вопрос плана о выпуске на правку
комментариев всё ещё ждёт решения агента mission.
