# 0083 — комментарии общей части проверок (модуль M9a)

**Запрос.** Начать модуль M9 подплана `comments.md` — вспомогательные инструменты репозитория.
Взять первую часть по границе, которую отметит план, по обычным правилам (датировка через
`git blame`, отброс неактуального и неверного, английский язык, сжатие до того, что не выводится из
кода файла, поведение и данные не трогаются) и отдельно проверить, не повторяется ли там та же
копипаста обоснований, что нашлась в проходе M8.

**Граница части (записана в подплан).** План оценивал M9 в «три-четыре коммита», но оценка делалась
до измерений, а бюджет коммита жёсткий (≤ 600 изменённых строк, ≤ 10 файлов). По прежним проходам
правка комментариев даёт 60–80 % от числа строк файла, поэтому части вышли такими:
M9a — `harness.js`, `run-tests.js`, `suites.js`, `check-standards.js` (752); M9b — `docs-facts.js`,
`gate-probe.js`, `page-harness.js`, `refusals.js` (742); M9c — `make-fixture.js`, `parity-freeze.js`,
`yaml.js` (611); M9d — `parity-live.js`, `pack-check.js` (419); M9e — `tools/gates/**` (769, 7 файлов);
M9f — `tools/synthetic/**` (405). Итого шесть проходов вместо трёх-четырёх — по бюджету, а не по
вкусу; порядок прежний: сначала то, что читают первым, гейты и синтетика последними.

**Сделано.** Строк до → после: `tools/harness.js` 285 → 275, `tools/run-tests.js` 185 → 181,
`tools/suites.js` 104 → 99, `tools/check-standards.js` 178 → 173; часть 752 → 728. Диффом
проверено: **ни одной** строки кода не тронуто — правка целиком в комментариях.

**Что исправлено (правда, а не язык):**

- `tools/harness.js`, правило про git: было «единственный вход к git» и «читать git в обход этого
  списка нечем». Сверено с кодом и сторожем: зовов три (`gitIn`, `gitTry` — закреплённые, и
  `gitBare` — заведомо незакреплённый), а `test/git-pins.test.js` требует, чтобы каждый прямой зов
  git шёл через общий список закреплений или через `gitBare`, и разрешает незакреплённый зов ровно
  в двух файлах (`tools/harness.js`, где `gitBare` и живёт, и `test/environment.test.js`, который
  измеряет унаследованные настройки). Сказано это, а не «входа один».
- `tools/harness.js`, окружение замороженной копии: было «до починки B1 иначе не воспроизводится» —
  номер правки из плана и без самого закрепления. Сверено с `tools/parity-freeze.js`, который снимал
  эталон: копия запускается с `core.quotePath=false`, потому что она старше закрепления, которое
  движок ставит себе сам, и на машине с умолчаниями git эталон молча потерял бы строку. Сказано это.
- Оттуда же убраны ссылки на документы, переписываемые этой же работой (`REFACTOR.md` R-1.5,
  `WORKLOG.md` §21): правило осталось словами, а живая ссылка на проверку (`test/runner.test.js`)
  сохранена.
- `tools/check-standards.js`, шапка: «построчное сравнение байтов было бы зелёным на одной версии git
  и красным на другой — это и случилось в CI» — проверено по архиву журнала (проход 22): на ubuntu
  упал именно `history.bundle`, сравнивавшийся побайтово, а `manifest.json` разошёлся из-за записанного
  в нём хеша бандла, тогда как конфиг, эталонные числа и хеш артефакта совпали. Утверждение верно,
  оставлено без номера раздела.

**Копипаста обоснований — проверена измерением.** Поиск одинаковых строк комментариев по дереву даёт
всего два совпадения (обе строки короткие и в проверках), а поиск повторяющихся восьмисловных
фрагментов внутри `tools/` — четырнадцать. Все они оказались **верными пересказами**, которые нужны
каждому файлу по отдельности (файл читают сам по себе): «жёлто-зелёное здесь и красное на машине с
настройками по умолчанию» (`gate-probe.js` и `gates/common.js`), «так же тихо, как расходятся любые
две копии» (`run.js`, `make-fixture.js`, `yaml.js`), «`core.quotePath=false`, у копии нет починки»
(`make-fixture.js`, `parity-freeze.js`), «JSON не совпал ничего не говорит о причине»
(`harness.js`, `check-standards.js`). Мёртвого обоснования, подобного найденному в M8, здесь нет;
вторые копии этих пересказов будут прочитаны в своих частях (M9c, M9e).

**Одна оговорка про язык, записанная нарочно.** В двух комментариях русского текста осталось не
ради объяснения, а как **цитата данных**: пример зова `--test-name-pattern=паритет` (шаблон обязан
совпадать с русскими именами проверок, иначе пример перестанет быть верным) и цитата сломанной формы
счётчика «1 проверок» рядом с «5 проверок». Это не проза, а цитируемое значение; объяснения вокруг
них английские.

**Проверено.** `git diff`: изменены только строки комментариев; `pnpm run verify:fast` зелёный
целиком (5 шагов, 72 проверки из 177).

**Предложено.** Следующая часть — M9b: `tools/docs-facts.js`, `tools/gate-probe.js`,
`tools/page-harness.js`, `tools/refusals.js` (742 строки). Там первым предметом сверки будет
