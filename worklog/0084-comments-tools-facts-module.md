# 0084 — комментарии инструментов: факты, проба, стенд, отказы (модуль M9b)

**Запрос.** Пройти часть M9b подплана `comments.md` — `tools/docs-facts.js`,
`tools/gate-probe.js`, `tools/page-harness.js`, `tools/refusals.js` — обычными правилами
(датировка, отброс неактуального и неверного, английский язык, сжатие, поведение и данные не
трогаются), отдельно сверить `tools/refusals.js` (он считает знаки отказа по исходникам) и
проверить, не повторяется ли там копипаста обоснований из прохода M8.

**Сделано.** Строк до → после: `tools/docs-facts.js` 218 → 214, `tools/gate-probe.js` 66 → 66,
`tools/page-harness.js` 116 → 116, `tools/refusals.js` 342 → 341; часть 742 → 737. Диффом
проверено: изменены только строки комментариев — ни одной строки кода. Гейт-файлов среди этих
четырёх нет (список гейт-файлов: пороги, базы, `package.json`, `tools/suites.js`, `tools/gates/`,
`test/gates-*`), поэтому трейлер `Gate-Change:` в этом проходе не требовался.

**Данные не тронуты — и это здесь доказуемо, а не на слово.** Каталог отказов держит две карты
чисел: `SITES` (броски) и `PRINTED` (печатаемые отказы). Числа сверены с исходниками измерением, а
не памятью: `'✗ '` встречается в `src/cli.js` 2 раза, `src/modes.js` 2, `src/check.js` 1,
`src/doctor.js` 2, `src/hook.js` 4 — ровно то, что в карте `PRINTED`. Отсюда прямой ответ на вопрос
прохода: за все предыдущие проходы ни один знак отказа, ни одна причина и ни одна фраза `must` не
менялись — иначе проверка `test/refusals-catalog.test.js` (тот самый счёт) была бы красной. Тексты
`truth`, `why`, `must` и советы — русские, это данные, и в дифф не попала ни одна такая строка.

**Найдено неверное (не язык, а правда):**

1. `tools/docs-facts.js`, «вне проверки два документа»: на деле их три — не назван
   `docs/requirements.md` (сверено: он есть в дереве, в `DOCS` его нет, а в `TARGETS` он есть —
   числа документа не проверяются, адреса разделов проверяются). Теперь названы все три с причиной
   у каждого.
2. `tools/docs-facts.js`: убраны адреса в документы, которые переписывает эта же работа
   (`REFACTOR.md` R-1.5, `WORKLOG` §59, `§B3`), а сами правила оставлены словами. Ссылка на
   закрытую запись блокеров хуже ссылки на живое: номера разделов уедут при переводе markdown.
3. `tools/gate-probe.js`: «пять копий» — тогда как обвязку берут **шесть** файлов проверок
   (сверено поиском); число убрано («копия на пробу»), заодно убрана отсылка к R-1.1 в той же
   фразе — сравнение «так же тихо» осталось и без номера.
4. `tools/page-harness.js`, про jsdom: было «остальным проверкам он не нужен и не оплачивается».
   Неверно: jsdom грузится всяким, кто импортирует этот файл, а за `contractData` сюда приходят и
   два набора контракта, которым DOM не нужен. Сказано то, что верно. Там же: «каждый из четырёх
   наборов» — `reportSetup` зовут только наборы страницы (трое).
5. `tools/refusals.js`, у отказа «нечем звать инструмент»: **та же мёртвая копипаста**, что
   нашлась в M8, — «имя пакета в реестре занято чужим пакетом, и `add -D <имя>` поставил бы его».
   Это шестое место, и оно нашлось поиском по слову «занят» уже после правки пяти прежних; поиск
   по дереву теперь не находит этой формулировки нигде. Новая причина — та же, что в `src/project.js`:
   зов по имени идёт в реестр и запускает ревизию, которой проект не закреплял. Заодно отброшена
   ссылка на `test/docs-pin.test.js` в этой фразе: сторож проверяет, что пример установки в README
   равен адресу из манифеста, а не то, что совет отказа называет ту же строку.
6. `tools/refusals.js`, о знаке «!»: было «это не отказ, а примечание (…) и свой код выхода у него
   нулевой». Неверно дважды: у примечания о приближении код **4** (`EXIT.SENSOR` — иначе
   приближение уехало бы в CI успехом; тот же каталог объявляет этот случай с кодом 4), а
   «выключенная автоматика» печатается в диагностике знаком «·», не «!». Вместо одного ложного
   общего утверждения сказано устройство: примечание отказа не образует, а что оно делает с кодом —
   по случаю (черновик и выведенные настройки вердикт не двигают, у оценки он 4).
7. `tools/refusals.js`, шапка: перечень «четыре раза (B1, B3, разбор аргументов, `explain HEAD`)»
   нёс номера разделов документов, которые переписываются. Сам факт оставлен и сверен по архивному
   журналу (проходы 42–43: ложная или пустая причина четыре раза, каждый раз случайно), номера убраны.

**Копипаста обоснований — перепроверена.** Кроме шестого места выше, ничего мёртвого здесь нет:
четыре прежние пары пересказов («жёлто-зелёное здесь и красное на машине с умолчаниями»,
«так же тихо, как расходятся любые две копии», «`core.quotePath=false`», «JSON не совпал ничего не
говорит о причине») прочитаны ещё раз и верны; их вторые копии в `tools/gates/common.js`,
`tools/run.js` (уже пройден), `tools/make-fixture.js`, `tools/parity-freeze.js`, `tools/yaml.js`
читаются в своих частях (M9c, M9e).

**Сверено с кодом и оставлено как верное.** Числа `SITES`/`PRINTED` и механизм счёта (рекурсивный
обход дерева git, `src/refusal.js` не считается); порядок случаев — по группам `CONFIG_CAUSES` (обе
группы в одном порядке); `truth` машиной не проверяется (в проверке он только упомянут); совет
берётся из вывода по маркерам, поэтому совет без маркера в каталог не попадёт; в таблице прогонов
README секунд нет (иначе обещание, которого не держит `tools/suites.js`); имя и адрес установки
берутся из манифеста (`src/tool.js`), а `docs-pin` сверяет с README ровно адрес.

**Проверено.** `git diff`: изменены только строки комментариев; кириллицы вне комментариев в диффе
нет; `pnpm run verify:fast` зелёный целиком (5 шагов, 72 проверки из 177).
