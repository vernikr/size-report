# 0095 — проверки: сторожа документации и выпуск (M10e)

**Запрос.** Пройти часть M10e нарезки — сторожа документации и выпуск. План мерит её семью файлами
(`docs-commands` 48, `release` 40, `templates` 39, `changelog` 25, `docs-numbers` 15, `docs-pin` 13,
`docs-paths` 12 — 192 строки комментариев). В поручении названо «три файла»; это единственное место, где
оно расходится с планом, — остальные числа (192 строки, ≈ 400 изменённых строк) совпадают с планом
точно, поэтому пройдены все семь, как в нарезке: семь файлов и 370 строк изменений укладываются в
бюджет коммита с запасом.

**Сделано.** `docs-commands` 183 → 177, `release` 141 → 137, `templates` 166 → 162, `changelog`
123 → 125, `docs-numbers` 53 → 52, `docs-pin` 63 → 61, `docs-paths` 66 → 65; 192 строки комментариев
дали **370 изменённых строк** (177 добавленных, 193 удалённые) в семи файлах. Диффом показано:
изменены только строки комментариев. Кириллица осталась лишь внутри данных: имена проверок, тексты
утверждений, разбираемые образцы (заголовок выпуска, шаблон зова, строки `README.md`) и русские
строки, по которым проверки сверяют сообщения.

**Первая находка: у обещаний документации были порядковые номера из списка, которого больше нет.**
`docs-paths` называл своё обещание «первым», `docs-numbers` — «четвёртым», `docs-pin` — «пятым»,
`changelog` — «шестым», а `docs-commands` перечислял четыре обещания внутри себя. Меж тем README
говорит «по файлу на обещание» и называет сторож выпуска **пятым**, а план — «по обещанию в файле».
То есть четыре файла ссылались на нумерацию прежнего единого сторожа, которая разошлась и между собой,
и с документацией. Номера убраны, каждое обещание названо словами: существование названного, зовы из
справки, причины отказа, числа, пин, версия с замером в журнале выпуска.

**Вторая: сторож документации сам называл несуществующий путь.** Шапка `docs-commands` объясняла, какие
документы не проверяются на зовы, и называла среди них `WORKLOG.md` — файла в корне нет с тех пор, как
журнал переехал в `worklog/archive/`; и в списке проверяемых на пути его нет вовсе (там README,
`PLAN.md`, `REFACTOR.md`, `BLOCKERS.md`, шаблоны и `CHANGELOG.md`). Перечисление убрано, осталось
правило: зовы проверяются только в инструкциях, прочие документы говорят о целевой поверхности,
истории или прошедшем.

**Третья: два адреса в документ, который переписывает эта же работа.** `templates.test.js` дважды
ссылался на `REFACTOR.md` R-4.21, объясняя, почему зов идёт путём внутри проекта, а не именем пакета.
Существо осталось (имя уходит в реестр и тянет пакет по сети), адрес ушёл.

**И одно удаление лишнего повтора.** `docs-numbers` объяснял правило «проверка объявляется в начале
строки» дважды — в шапке и в первом комментарии тела; осталось в теле, где это и проверяется.

**Датчик поймал меня, и это стоит записать.** После правки красным стал шаг `metrics`: у одной функции
в `test/templates.test.js` оказался **61** строка при пределе 60 — потому что строки комментариев внутри
функции входят в её длину. То есть проход по комментариям умеет ломать датчик размера, ничего не меняя
в коде. Починка — сжать сами комментарии внутри функции (61 → 57), а не трогать порог: датчик прав,
комментарий внутри функции — часть её объёма.

**Что сверено по коду и осталось.** Реестр причин один: `CONFIG_CAUSES`, справка печатает их из него,
таблица кодов README сверяется с тем же списком — и обратная сторона (причина, которую никто не выдаёт)
проверяется по исходникам. Шаблоны сравниваются побайтово в `tools/pack-check.js` — значит «доезжает ли
шаблон до поставки, дело `pack-check`» верно. Сторож пина читает справку **закреплённой ревизии** из
истории git (не из дерева), а пин берёт из примера установки в README и сверяет с `installSpec()`;
короткий sha pnpm разрешает только через видимые рефы — это и объясняет требование сорока знаков.
Пути из документации сверяются с деревом, с историей фикстуры (её история — не одно дерево, поэтому
имя до переименования законно) и со списком чужих, который ведёт человек.

**Проверено.** `git diff`: изменены только строки комментариев; `pnpm run verify:fast` зелёный целиком
(5 шагов, 72 проверки из 177), полный профиль — зелёный целиком (8 шагов, 70,6 с). Трейлер
`Gate-Change:` не понадобился: гейт-файлов среди правки нет — сверено списком (из тестов там только
`test/gates-*.test.js`, они в следующей части).

**Предложено.** Следующая часть — **M10f**: пробы самих датчиков (`gates-metrics` 46, `gates-verify` 31,
`suites` 22, `gates-files` 21, `gates-dup` 12, `gates-coverage` 11, `gates-deps` 10 — 153 строки
комментариев, ≈ 310 изменённых строк). Все семь — гейт-файлы, поэтому коммиту понадобится трейлер
`Gate-Change:` с замером.
