# 0102 — документация: страница отчёта в README (M4a)

**Запрос.** Пройти остаток раздела о состоянии, где утверждения держатся на числах настоящего
браузера: страница отчёта, дерево файлов, складывание, порядок колонок, широкая раскладка, память
выбора и ссылка. Сначала замерить, потом решить, что из чисел вообще нужно читателю. Границу задаёт
бюджет коммита.

**Решение по числам: их не перемерять, а отдать правилу.** Каждое из них я проверил по коду — и почти
все они суть измеренный симптом, а не знание о работе инструмента: «панель 883 px, страница 1097 при
окне 900, под таблицей 195 px» было свойством прежней раскладки, «клик 0,6 мс против 107 + 380 мс
перерисовки», «`panel.scrollTop` 421 до и после», «1060 × 735», «25 колонок и итог 994 335»,
«`size-report:4684b2b2`» — снимки одной машины и одной ревизии. Читателю нужны правила, из которых эти
числа следовали, а правила лежат в коде и потому не стареют. Замерять заново я ничего не стал
намеренно: обвязки настоящего Chrome в репозитории нет (`tools/page-harness.js` — это jsdom для пяти
наборов), то есть повторный замер был бы замером ради числа, которого в документе не останется.

**Числа.** README 1050 → 1012 строк, кириллицы 711 → 578 (133 русских строки), дифф `README.md`
102/140 — **242 изменённых строки в одном файле** при бюджете 600. Ничего
из существа не потеряно: каждая снятая цифра заменена своим правилом, и **каждое правило сверено по
коду**, а не перенесено из прежнего текста.

**Что проверено и осталось словами.** Один набор стилей таблицы на оба вывода (`src/table.css`,
заморожен байтами артефакта — `src/css.js`), липкие шапка и колонка коммита, сужение колонки коммита в
узком окне (300 → 190 px). Два состояния пустоты (`appUi.empty` при снятых метриках, `appUi.noFiles`
при снятых файлах — `src/page/table.js` `appState`). Переключатель — метка вокруг поля ввода, поэтому
мышь, `Space` и вспомогательные технологии попадают в одно место (`src/page/dom.js` `appBox`), а у
недоступного поля подсказка стоит на всей строке: браузер не показывает её у выключенного поля
(`appOffBox`). Дерево строится по каталогу — всякому пути, который видит git, — а не по колонкам
(`src/project.js` `projectTree`): отсюда и место для файлов вне отчёта, и причина в подсказке (`rule` —
сгенерированное или больше предела, `choice` — выбор проекта). Сам отчёт в каталоге всегда, и именно
поэтому страница не должна зависеть от его отслеживаемости: иначе первая же пересборка в свежем клоне
дала бы другие байты. Счётчик папки долей, три состояния папки, снятое после того, что в отчёте,
свой знак у папки, складная запись под своим ключом и тем же паспортом — всё в `src/page/panel.js` и
`src/page/state.js`. Складывание — класс на строке (`.panel .tree li.folded > .tree { display: none }`),
и клик меняет ровно три вещи, которые видит читатель. Сетка на `body` с пятью названными строками и
порог 899/900 — в `src/page/app.css`, там же и причина порога: при ровно 900 px обе половины
оформления применились бы к одной странице. Прокрутка как часть вида и возврат фокуса без прокрутки
(`preventScroll`) — в `src/page/app.js`. Паспорт отчёта (имя инструмента, схема, путь артефакта,
заголовок, метки колонок) и запись только выключенного по именам — в `src/page/state.js`; ссылка —
эта же запись в якоре, ссылка старше памяти, чужой адрес объясняется строкой и не переписывается.
«Ни одного обращения в сеть» осталось, но как **утверждение проверки**: `test/page-view.test.js` (нет
`https?://` в тексте страницы) и `test/parity.test.js` (то же для артефакта). Отдельно сверено, что
порядок «колонки последнего коммита впереди» берёт последний коммит, задевший хотя бы одну колонку, и
**почему** пропускает коммиты мимо колонок: иначе знак зависел бы от коммита самого отчёта, тот же
прогон давал бы другие байты, и хук коммитил бы отчёт второй раз (`src/history.js`).

**Проверено.** `pnpm run verify:fast` зелёный (5 шагов, 72 проверки из 177), полный профиль — зелёный
целиком (8 шагов, 59,7 с). Гейт-файлов в коммите нет, трейлер не нужен.

**Предложено.** Остаток M4 — `min`, `tok`, волна 0, команды полноты и объяснения, хук — идёт следующим
проходом: там числа другого рода, их можно перемерить на фикстуре (`fixtures/synthetic` + `--config` с
`"minify": {"engine": "esbuild"}` и без него, два словаря токенов), а числа времени на живой истории и
стоимость набора (**«7,3–7,9 → 10,4 с при 66 → 73 проверках»**) уже разошлись (сегодня 177 проверок) и
подлежат замене правилом, как это сделано здесь. Развилка для решения: в этом разделе есть абзацы с
такими же числами времени, что я убрал, — оставлять ли перемеренное время хоть где-нибудь, или в README
не обещать секунд вовсе (как и говорит сам документ о прогонах).
