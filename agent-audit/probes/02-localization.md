# Зонд 02 — Локализация правки по истории

Цель: измерить навигационную эффективность — находит ли агент нужные файлы
по описанию задачи и какой ценой. Основание: разведка — отдельная дорогая фаза
(обзор затрат токенов: фазы Explore/Fix — самые дорогие); качество разведки
предсказывает успех починки (SWE-Explore); дешёвый разведчик экономит 84–95%
токенов без потери качества (IssueLoc-Bench).

## Подготовка золотых задач

```sh
# кандидаты: коммиты за полгода, тронувшие 1–5 файлов кода (без документации)
git log --no-merges --since='180 days' --pretty='@@ %H | %s' --numstat \
| awk -F'\t' '/^@@/{if(files>0&&files<=5&&code>0)print buf; buf=$0; files=0; code=0; next}
  NF>=3{files++; if($3 !~ /\.md$/ && $3 !~ /lock/) code++}
  END{if(files>0&&files<=5&&code>0)print buf}'
```

Для каждого отобранного коммита: `задача = сообщение коммита` (убрать имена файлов
и другие подсказки!), `золото = список файлов из --numstat`.

## Протокол (полуавтомат)

Вариант А — вручную: новая сессия, промпт:

```
В этом репозитории нужно выполнить задачу: «<задача>». Ничего не меняй.
Назови не более трёх файлов, в которые, вероятнее всего, придётся вносить
изменения, в порядке уверенности, и одной фразой — почему.
```

Вариант Б — headless (повторяемо и с метриками затрат):

```sh
codex exec "… тот же промпт …"    # или: claude -p "…", gemini -p "…"
```

## Оценка

- **Hit@3** = 1, если хотя бы один золотой файл попал в топ-3 ответа.
- По возможности — число вызовов инструментов и токены на задачу.

`Локализация = (число попаданий / число задач) × 100`; эффективность —
медиана затрат. Пороги ориентировочные: ≥70% — хорошо; 50–70% — навигация
хромает (дубли имён, плохие точки входа); <50% — структура нечитабельна.

Сравнение одного и того же набора задач между версиями документации репо даёт
прямую дельту «что дала ваша работа над контекстом».
