# Зонд 04 — Мелкая починка с обратной связью

Цель: измерить полный цикл «понять → найти → починить → проверить» на реальной
мелкой задаче. Основание: проверяемость — наибольший рычаг качества агента
(практика Claude Code); фиксация и проверка — самые дорогие фазы по токенам,
поэтому скорость зелёной петли определяет и цену, и успех.

## Протокол

1. Взять подготовленную мелкую починку (`00-prepare.md`, пункт 3).
2. Новая сессия. Промпт — формулировка задачи в терминах продукта/дефекта,
   без подсказок о месте. Добавить стандартную для репо фразу
   «проверь свою работу» — и смотреть, найдёт ли агент сам, чем проверять.
3. Фиксировать:
   - число ходов до первой зелёной проверки;
   - использовал ли агент правильный командный вход (из контекст-файла),
     или подбирал/выдумывал команды;
   - прочитал ли лишнее (файлы >8K токенов целиком — маркер мин из статики);
   - итог: починено с первого захода / после итераций / не починено.

## Оценка

| Компонент | Баллы |
|---|---|
| Починено и проверено с первого захода | 4 |
| Починено после ≤3 итераций | 2 |
| Не починено или сломано другое | 0 |
| Правильный командный вход найден сам | +1 |
| Не читал «мины» целиком | +1 |

`Починка = баллы / 6 × 100`.

Диагностика: агент не нашёл, чем проверять → в точке входа нет команды проверки
(метрика E1 статики); читал гигантские файлы → мины работают (метрики C1–C3).
