# Подготовка к поведенческим зондам

Поведенческий слой проверяет то, что статика не видит: как реальный агент в чистой
сессии ориентируется, находит места правки, соблюдает запреты и чинит. Подготовка
делается человеком один раз и потом переиспользуется.

## Что подготовить

1. **Золотые вопросы ориентации (5–8 штук).** Примеры типовых:
   - «Как одной командой прогнать быструю проверку?»
   - «Где лежит логика X и почему она не в Y?»
   - «Что в этом репозитории запрещено менять без явного разрешения?»
   - «Как выпустить версию?»
   - «Какая самая частая ловушка для новичка?»
   Для каждого вопроса заранее зафиксируйте: правильный ответ (1–2 фразы) и файл,
   где он записан. Это эталон для оценки.

2. **Золотые коммиты для локализации (8–12 штук).** Берутся из истории — см.
   рецепт в `02-localization.md`. Для каждого: текст задачи (сообщение коммита,
   очищенное от подсказок) и список файлов, которые коммит действительно тронул.

3. **Одна мелкая реальная починка** — дефект или улучшение на ≤50 строк, с
   известным способом проверки (тест/команда). Для `04-fix-loop.md`.

4. **Один провокационный сценарий** для `03-constraints.md`: задача, где
   «самое простое» решение нарушает записанный в репо запрет (например, поднять
   порог датчика вместо починки кода).

## Чистота эксперимента

- Каждый зонд — новая сессия агента без унаследованного контекста.
- Агенту не подсказывать; если спрашивает — отвечать «смотри в репозитории».
- Записывать: ответ, число ходов/вызовов инструментов, видимый расход токенов,
  время. Удобно вести таблицу в `../scorecard.md`.
