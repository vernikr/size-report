# Пример аудита: `vernikr/size-report` — 2026-09-15

Прогон комплекта версии 1 на самом репозитории (дог-фудинг: пакет считает размеры
и токены — сам себе объект аудита). Полный вывод — `scan-size-report.json`;
токены — эвристика ±20%.

## Скоркарта (статика)

| Измерение | Баллы | Комментарий |
|---|---|---|
| Входной контекст | 12/20 | AGENTS.md есть, 2.7K ток. (верхняя граница); README — 54K ток., вне бюджета |
| Достоверность | 9/25 | 178 мёртвых ссылок из 322 (55%); 2 команды в README вне манифеста |
| Масса и отвлекатели | 0/20 | 4 файла-«мины» >32K ток.; корневые доки суммарно 451K ток. |
| Находимость | 7/15 | уникальность имён 94% (порог 95%); каталоги неглубокие и негустые |
| Обратная связь | 20/20 | тесты, 3 воркфлоу, локфайл, пины, .githooks |
| **Итог** | **48/100 — D** | без поведенческих зондов: «только статика» |

История: клон сжат в один коммит, статистика недостоверна (N/A); заявленная
норма репо — ≤600 строк / ≤10 файлов на коммит — агентно-дружественная.

## Главные находки

1. **Журналы — мины контекста.** `WORKLOG.md` ≈212K ток., `REFACTOR.md` ≈79K,
   `PLAN.md` ≈47K, `BLOCKERS.md` ≈17K. Любая попытка агента «прочитать для
   понимания» упирается в рот контекста: деградация идёт даже на релевантном
   тексте (Context Rot), а длина вредит даже при идеальном поиске (арХив 10/2025).
   При этом ценность журналов — в точечном поиске по ним, а не в чтении.
2. **Дезинформация в точке входа.** В `README.md` упомянуты команды
   `pnpm run sizes` и `pnpm run test:sizes`, которых нет в `package.json`.
   Неверная команда хуже отсутствия: агент исполнит её, получит ошибку и начнёт
   «чинить» несуществующее (−22.6 п.п. успеха по данным о неверных доках).
3. **Мёртвые ссылки в журналах** (старые имена `@vernikr/size`, `repo-size`,
   пути соседних рабочих каталогов `../figma/safe-resets/...`, `/tmp/...`).
   Сами по себе они — следствие честной истории, но без объявленной границы
   «это архив» агент будет им доверять.
4. **Сильная сторона — петля обратной связи** (20/20): быстрые/полные/медленные
   гейты, хуки, детерминированные базы. Это наибольший рычаг качества агента
   (практика Claude Code) — он уже вложен, терять нельзя.
5. **Неоднозначные имена** (10 дублей основ: `config`, `data`, `history`,
   `README`...) — мелкий, но постоянный налог на навигацию (порог 95% не взят).

## Топ-3 точки роста (по рычагу)

1. **Объявить границы журналов в AGENTS.md** (одно дополнение, ~5 строк):
   «WORKLOG/REFACTOR/PLAN/BLOCKERS — архивы решений; не читать целиком, только
   точечный поиск `rg`; актуальные правила — в этом файле и `docs/`».
   Эффект: защита от мин (1) и (3) без удаления истории; основание — высокая
   послушность агентов запретам (исследование ETH) и цена отвлекающих токенов.
2. **Починить команды в README** (`sizes`, `test:sizes` → реальные имена) и
   пройтись по списку мёртвых ссылок сканера в не-журнальных документах.
   Самый дешёвый выигрыш по достоверности.
3. **Быстрый вход в начало README**: первые ~15 строк — что это, три команды,
   куда смотреть дальше (агент читает начало окна надёжнее середины —
   «Lost in the Middle»). Остальное не трогать: это документация для людей.

Что не трогать: структуру `src/` (плоская, глубина 2, модули ≤410 строк —
репо-карта дешёвая), гейты, хуки, выпуск.
