# BLOCKERS — size-report

Журнал блокеров и известных пробелов. Запись здесь — это то, что нельзя закрыть
умолчанием: либо работа стоит, либо дефект известен и обойдён так, что забыть о
нём не получится.

Правила ведения:

- у каждой записи есть **воспроизведение** (команда, а не рассказ), **следствие**
  и **предлагаемая починка**;
- обойдённый пробел обязан держаться проверкой, которая упадёт, когда пробел
  закроют: иначе обход превращается в тишину;
- закрытая запись не удаляется: помечается датой и коммитом.

## B1. Пути вне ASCII зависят от `core.quotePath` — ОТКРЫТ

**Суть.** Движок берёт список изменённых файлов из `git log --name-only` и
полагается на настройку git `core.quotePath`. По умолчанию она **включена**, и
тогда git отдаёт не-английские пути закавыченными и экранированными:

```text
"docs/\320\267\320\260\320\274\320\265\321\202\320\272\320\270.md"
```

Такой строке путь из настроек (`docs/заметки.md`) не соответствует, поэтому
колонка с не-английским путём не находит файла ни в одном коммите.

**Воспроизведение.**

```bash
git clone fixtures/synthetic/history.bundle /tmp/size-report-b1
cd /tmp/size-report-b1
GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.quotePath GIT_CONFIG_VALUE_0=true \
  node ../../size-report/fixtures/legacy/size-table.cjs \
  --config ../../size-report/fixtures/synthetic/config.json --json | jq '.rows | length, .skipped'
```

С настройкой по умолчанию (то есть на машине, где `core.quotePath` не выключен
глобально) получается 13 строк вместо 14 и лишний пропуск.

**Следствие — две потери, а не одна:**

1. колонка с таким путём пустеет на всей истории: файла для инструмента будто не
   существует;
2. коммит, у которого эта колонка была **единственным изменением объёма**, теряет
   строку целиком (в фикстуре — «ветка — правка кода и заметок»): он попадает в
   список пропущенных как «без изменения объёма».

На живом проекте (`safe-resets`, все пути ASCII) дефект не проявляется — поэтому
эталон паритета с ним от этой настройки не зависит, а фикстура зависит.

**Обход (сделан).** Все сверки в `test/parity.test.js` идут с закреплённым
`core.quotePath=false`: тест обязан управлять входом, иначе он зелёный на одной
машине и красный на другой. Сама зависимость проверяется свидетелем
(«известный пробел B1»), который утверждает обе потери и упадёт, когда их
закроют, — тогда маркер снимут вместе с этой записью.

**Предлагаемая починка (отдельным проходом, не в переносе).** Читать пути из git
независимо от настройки: либо явно передавать `-c core.quotePath=false` в вызовы
`git log` в `history.js`, либо перейти на разбор с `-z` (пути через `\0`) — второе
заодно снимает вопрос о путях со переводами строк. Починка меняет поведение, а
значит требует собственного свидетеля и обновления эталона.

**Статус:** открыт. Внесён в план отдельным пунктом (см. `PLAN.md`, §5, шаг 1,
пункт D2).

## Заметки (не блокеры)

- **N1. Контрольный режим в свежем клоне фикстуры красный.** В фикстуре артефакт
  закоммичен (коммит «только отчёт» сдвигает его содержимое), поэтому до
  `--write` файл не совпадает с историей. Порядок проверок поэтому такой:
  `--json`, затем `--write`, затем контрольный режим — так же поступает и
  `tools/make-fixture.js`.
- **N2. Путь движка в тексте ошибки меняется при переносе.** Подсказка «создайте
  его: node … --init» печатает путь самого файла движка: было
  `tools/size-table.js`, стало `src/size-table.js`. Это текст сообщения, а не
  числа и не форма отчёта, и паритет-тест его не сверяет — но знать об этом
  полезно, чтобы не искать разницу в отчёте.
