## 2. Принцип: одно место на факт

> **Факт живёт ровно там, откуда его читает машина. В прозе остаётся только то, что не печатает
> ни одна команда.**

Отсюда следствия:

1. Если факт выводится (`git ls-files`, `--help`, счётчик тестов, бейзлайн) — его **нет в прозе**.
2. Если факт нельзя вывести (решение человека, причина порога, известный красный шаг) — он живёт
   **в коде рядом с решением** (комментарий) или **в машиночитаемом артефакте** (бейзлайн,
   `skip` у теста с причиной), а не в отдельном документе.
3. Указатель допустим только в форме, которую можно проверить `grep`: **путь** или **путь + символ**.
   Ссылок вида `§4.3` не существует — у них нет адресата, который можно проверить дёшево.

## 3. Что остаётся

### 3.1 Единственный документ — `AGENTS.md` (~120–150 строк)

Агенту на старте сессии нужны четыре вещи, и больше ничего:

1. **Чем проверить свою правку** — три команды профиля (`verify:fast` / `verify` / `verify:slow`).
2. **Что красное по решению человека и почему** — 2–5 строк, вместо `BLOCKERS.md` на 1 001 строку.
3. **Что нельзя трогать** — бейзлайны, пороги, `fixtures/**`, трейлер `Gate-Change:`.
4. **Как оформить результат** — conventional commit + трейлер; коммит-сообщение и есть журнал.

Правила для самого `AGENTS.md`, чтобы он не отрастал:

- **ни одной цифры**, которую печатает команда («сколько проверок» печатает `tools/run-tests.js`);
- **ни одной ссылки `§`**;
- только пути и команды, которые существуют;
- «что красное» — со сроком/владельцем решения, устаревшую строку удаляют, а не зачёркивают.

### 3.2 Машиночитаемые артефакты — остаются как есть

Тесты, фикстуры, бейзлайны (`.eslint-suppressions.json`, `dup-baseline.json`,
`coverage-baseline.json`), конфиги сенсоров, `reports/` (в `.gitignore`), `--help` (`USAGE` в
`src/refusal.js`), реестр причин отказов (`CONFIG_CAUSES`), заморозка API (`test/api.test.js`).
Это и есть настоящая документация поведения: она исполняется, поэтому не устаревает молча.

### 3.3 То, что не документация, а данные/поставка — не трогать

- `fixtures/synthetic/README.md` (43), `fixtures/parity/README.md` (20), `fixtures/live/README.md` (29) —
  сравниваются побайтово в `tools/check-standards.js` (`FIXTURE_FILES`), это замороженные данные.
- `templates/**` (в т.ч. `templates/README.md`, 87 строк) — уезжает в тарболл
  (`package.json: files = ["bin","src","templates","README.md","LICENSE"]`), охраняется
  `pack:check` и `test/templates.test.js`. Это поверхность продукта, не внутренняя проза.
- `LICENSE` (21) — уезжает в тарболл.

### 3.4 `README.md` — ужать до ~40–60 строк

Он уезжает в npm (`files`), поэтому совсем удалить нельзя. Оставить: имя, одна фраза «что это»,
строку установки, указание на `size --help`. Всё остальное (984 строки: инструкция на 8 разделов,
таблица кодов, таблица прогонов, таблица файлов, «ловушки») — удалить.
Строку установки **генерировать** из `installSpec()` шагом релиза, а не сверять сторожем.

## 5. Что делать со сторожами документации

Удалять 615 строк можно только вместе с артефактами, которые они охраняют: нет прозы — нечего
сверять. Но внутри них есть две проверки **код↔код**, которые стоит сохранить, перенеся в
существующие файлы (это правки кода, в этом документе они только описаны):

**Сохранить (ценность реальная, проза не участвует):**

- причины отказов: движок ↔ справка ↔ фактически выдаваемые `refuseCause('…')`
  (сейчас третья проверка в `test/docs-commands.test.js`) — без половины про таблицу кодов README;
- список команд/ключей: `USAGE` ↔ то, что реально разбирает CLI;
- первая половина `test/docs-numbers.test.js` — «тест объявляется в начале строки» (это про
  читаемость набора机器ом, не про README).

**Удалить без замены:**

- сверка путей из прозы с деревом;
- таблица файлов README ↔ дерево в обе стороны (налог на каждый новый файл);
- ссылки `§` и весь `namedSection()`;
- пин установки (заменяется генерацией строки установки на релизе).

**Побочный эффект, который надо учесть:** `tools/docs-facts.js` после удаления четырёх тестов
станет сиротой, и сенсор зависимостей это увидит (`.dependency-cruiser.cjs`, правило `no-orphans`,
`tools/gates/deps.js`). Удалять файл нужно в том же коммите — сенсор сам проконтролирует.

**Замена всей обвязки — один сторож на ~25 строк** (негативный, чтобы проза не отросла):

1. в корне нет `.md`, кроме `README.md`, `AGENTS.md`, `LICENSE`;
2. ни в одном `.md` нет символа `§`;
3. каждый путь с расширением в backticks в `AGENTS.md`/`README.md` есть в `git ls-files`.

Три правила вместо 615 строк и 8 проверок, и они не требуют сопровождения чисел.

## 7. Риски и честные оговорки

- **Сторожа ловили реальное рассогласование** (класс B1: «документ называет то, чего нет»).
  Их потеря безопасна только потому, что исчезает сам класс артефактов. Поэтому волны 0 и 2
  должны идти вместе: удалить сторожа и оставить прозу — худший из вариантов (проза начнёт
  врать молча).
- **Проверки код↔код из раздела про сторожей документации надо перенести, а не потерять** — иначе причина отказа сможет
  разойтись со справкой.
- **`docs/size-report.html`** — продукт самого инструмента; решение «не отслеживать» меняет
  поведение хука, то есть это правка кода и, вероятно, гейтовый коммит.
- **Не проверено здесь:** полный профиль. В этой песочнице клон обрезан до одного коммита,
  поэтому `node tools/run-tests.js fast` даёт 9 падений, все — средовые:
  `test/frozen.test.js` падает с `the history has no fixtures/legacy/size-table.cjs: the copy the
  reference was taken with is nowhere to be had`, а `test/docs-pin.test.js` — с
  `пин «v2.4.0» — не ревизия и не ветка (тег) этого репозитория`. `pnpm` в песочнице нет, поэтому
  `pnpm run verify` не запускался. Утверждения о времени (`2.01 s`, `0.70 s`) — из запуска
  `node tools/run-tests.js fast` на 40 прошедших проверках из 70 объявленных.
- **Необратимость.** `git rm` журнала и планов обратим через историю, но после `gc`/переписывания
  истории — нет. Дешёвая страховка: тег `docs-before-purge` на последнем коммите перед волной 2.
