# size-report

Инструмент учёта роста объёма кода и документов: показывает, насколько вырос или
уменьшился проект в каждом изменении, в трёх разрезах — «как написано» (raw),
«в минифицированном виде» (min) и «в токенах для языковой модели» (tok).

Отвечает на два вопроса: человеку — «где проект распухает», ИИ-агенту — «сколько
весит моё изменение в его собственном контексте». Ничего не запрещает и не
блокирует: только показывает.

## Статус

**Шаг 1 плана пройден — перенос без изменения поведения.** Движок лежит в
`src/size-table.js`, команда — `bin/size.js`; паритет доказан автоматически:
`pnpm test` сверяет пакет с эталоном побайтово на фикстуре и в четырёх заведомо
чужих окружениях (настройки git машины, локаль), `pnpm run parity:live` — на живой
истории `safe-resets` в двух средах (95 строк × 27 колонок, артефакт байт в байт).
Вывод не зависит от настроек машины — настройки git, влияющие на разбор, закреплены
в самом движке (`BLOCKERS.md` §B1). Сверка с рабочим деревом сравнивает содержимое,
а не размеры, поэтому выкладка с переводами строк в CRLF (`.gitattributes`,
`core.autocrlf` — значение по умолчанию в установке Git для Windows) работе не
мешает (`BLOCKERS.md` §B2).

**Шаг 2 начат первым срезом — контрактом данных.** Движок отдаёт абсолютные
значения и устройство таблицы (`--data`), а дельты, суммы, «сейчас» и фильтры
считает страница (`--page`, `size-report.html` рядом с таблицей): без этого
фильтры и «итого по выбору» невозможны в принципе. Следующий срез — дерево файлов,
запоминание выбора и внешний вид; ещё не сделано — минификация и токены, разбиение
движка по файлам (пункт D1 в плане). Источник
инструмента —
`tools/size-table.js` в проекте [`safe-resets`](../figma/safe-resets) (1145 строк,
метрики `raw` и «упрощение вместо минификации», статичный отчёт в git).
**Пункты R-1.1 и R-2.1 волн 1–2** (`REFACTOR.md`): вычислительная часть отчёта одна
(`src/derived.js`) — страница исполняет тот же код, что считает статическую таблицу,
и разметку для неё строит обычный исходник `src/page/app.js`, а не строка внутри
движка; артефакт и разметка страницы при этом совпали со старым выводом побайтово.

**Волна 0 чистки пройдена** (`REFACTOR.md`): у отказов командной строки появились
коды выхода и справка вместо стека, `--help` отвечает, `--page` и `--write`
создают недостающий каталог, подсказка в отказе ведёт к работающей команде, а
черновик `--init` больше не предлагает колонкой саму таблицу — иначе первая же
проверка настроек его отвергала.

Перенос, доработка и оформление в пакет расписаны в `PLAN.md` по шагам, с
приёмкой каждого.

## Что в репозитории

| Файл | Роль |
|---|---|
| `PLAN.md` | **Главный документ:** инвентаризация, границы, инварианты, архитектура, семь шагов переноса, приёмка, риски, открытые вопросы |
| `docs/requirements.md` | Требования заказчика: что и зачем |
| `docs/module-design.md` | Архитектурный проект выноса: как устроен модуль |
| `WORKLOG.md` | Журнал запросов и сделанного |
| `BLOCKERS.md` | Открытые блокеры и известные пробелы (обход обязан держаться проверкой) |
| `REFACTOR.md` | Поканальный план чистки: объём кода, потом скорость; границы и чем доказывается, что поведение не изменилось |
| `tools/parity-freeze.js` | Снимает эталон паритета с живого проекта: `--json`, конфиг, хеш артефакта, хеш инструмента |
| `tools/make-fixture.js` | Собирает синтетическую фикстуру: детерминированную историю с ловушками плюс эталонные числа |
| `tools/parity-live.js` | Сверяет движок с живым проектом на клоне: числа и артефакт (`pnpm run parity:live`) |
| `fixtures/parity/` | Эталон с `safe-resets` на коммите `bd6ef9d`: 95 строк × 27 колонок |
| `fixtures/synthetic/` | Бандл фикстуры на 16 коммитов, её конфиг, эталонные числа и хеш артефакта |
| `fixtures/legacy/size-table.cjs` | Замороженная копия реализации, с которой снят эталон (сверяется по sha256) |
| `src/derived.js` | Общий расчёт отчёта: итоги, дельты, клетка, подпись коммита — одно место на артефакт и страницу |
| `src/page/app.js` | Программа страницы: разметка и состояние галочек; вклеивается в собранную страницу |
| `test/parity.test.js` | Паритет-тест: числа, артефакт, локаль, герметичность окружения и сверка с рабочим деревом |
| `test/contract.test.js` | Контракт данных и страница: числа против эталона, производные против чисел артефакта |
| `package.json` | Манифест пакета (версия `0.0.0`: отдельного релиза ещё не было) |

Оба каталога эталонов пересобираются побайтово: `pnpm run parity` и `pnpm run fixture`
дают те же файлы (проверено повторным прогоном — рабочее дерево остаётся чистым).

## Чего ещё нет

```text
dist/app.js        пре-собранная программа отчёта для публикации
templates/         черновик настроек, блок для AGENTS.md, шаблон CI
```

Внутри движка пока нет линтера и разбиения на модули (пункты R-1.2 и R-1.3
`REFACTOR.md`), а метрики и оба отчёта — статичный артефакт и страница —
считаются на сборке: страница получает исходники общего расчёта и своей
программы вклеенными (`src/derived.js`, `src/page/app.js`), потому что открывается
она с диска, без сервера и без сети. Остальное — по шагам 2–6 (`PLAN.md` §5).

## Как это будет выглядеть для проекта

```bash
pnpm add -D size-report   # установка
pnpm exec size init       # найти файлы, создать настройки, вписать .size-report/ в .gitignore
pnpm exec size update     # посчитать и собрать отчёт (или это сделает post-commit)
```

Отчёт — один файл, открывается двойным щелчком, без сервера и без сети. В git он
не попадает: это выводимый артефакт, который всегда можно пересобрать из истории.

## Для ИИ-агента

- `size measure --json` — данные без вёрстки: строки, числа, суммы. Сегодня это
  `--json` (прежняя форма, заморожена эталоном) и `--data` (контракт страницы).
- `size check --json` — готова ли среда и покрыты ли все файлы истории.
- `size doctor --json` — вся диагностика одним ответом.
- Коды выхода: `0` всё хорошо · `1` расхождение с историей · `2` настройки или
  окружение · `3` неполная история · `4` нет датчика · `5` внутренняя ошибка
  (таблица — `PLAN.md` §4.1). Действуют уже сейчас: отказ — это код и одна строка
  с готовой командой починки, без стека. `--help` печатает и то, и другое.

## Ловушки, на которых стоит проверять движок

Фикстура (`fixtures/synthetic/history.bundle`) — это история, в которой
собрано то, на чём ломаются такие инструменты: `//` внутри строки, регексп с
экранированным слэшем, шаблон с выражением, `.mjs` с `export`, не-английское имя
файла, CRLF, переименование файла, коммит «только отчёт», смешанный коммит,
слияние с правкой разрешения конфликта, замена символа без изменения объёма,
удаление и возврат файла, пустой файл, незнакомое расширение. Полный список — в
`fixtures/synthetic/README.md`.

```bash
pnpm test                      # паритет на фикстуре: числа, артефакт, чужое окружение,
                               # сверка с рабочим деревом и её зубы; контракт данных
                               # и страница (в том числе в настоящем DOM)
pnpm run parity:live           # паритет с живым проектом на клоне, две среды
node bin/size.js --data        # контракт данных: страница и агент
node bin/size.js --page        # минимальная страница отчёта
node bin/size.js --help        # справка и коды выхода
git clone fixtures/synthetic/history.bundle /tmp/size-report-fixture
node tools/make-fixture.js     # пересобрать фикстуру и эталон
```

Открытые блокеры и известные пробелы — в `BLOCKERS.md`; там же таблица настроек,
которые проверены и оказались инертными (чтобы не проверять их заново).
