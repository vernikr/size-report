# size-report

Инструмент учёта роста объёма кода и документов: показывает, насколько вырос или
уменьшился проект в каждом изменении, в трёх разрезах — «как написано» (raw),
«в минифицированном виде» (min) и «в токенах для языковой модели» (tok).

Отвечает на два вопроса: человеку — «где проект распухает», ИИ-агенту — «сколько
весит моё изменение в его собственном контексте». Ничего не запрещает и не
блокирует: только показывает.

## Как это будет выглядеть для проекта

```bash
pnpm add -D size-report   # установка
pnpm exec size init       # найти файлы, создать настройки, вписать .size-report/ в .gitignore
pnpm exec size update     # посчитать и собрать отчёт (или это сделает post-commit)
```

Отчёт — один файл, открывается двойным щелчком, без сервера и без сети. В git он
не попадает: это выводимый артефакт, который всегда можно пересобрать из истории.

## Для ИИ-агента

- `size measure --json` — данные без вёрстки: строки, числа, суммы.
- `size check --json` — готова ли среда и покрыты ли все файлы истории.
- `size doctor --json` — вся диагностика одним ответом.
- Коды выхода стабильны: `0` всё хорошо · `1` нарушение полноты · `2` настройки ·
  `3` неполная история · `4` нет датчика · `5` внутренняя ошибка. Текст ошибки
  содержит готовую команду починки.

## Ловушки, на которых стоит проверять движок

Фикстура (`test/fixtures/synthetic/history.bundle`) — это история, в которой
собрано то, на чём ломаются такие инструменты: `//` внутри строки, регексп с
экранированным слэшем, шаблон с выражением, `.mjs` с `export`, не-английское имя
файла, CRLF, переименование файла, коммит «только отчёт», смешанный коммит,
слияние с правкой разрешения конфликта, замена символа без изменения объёма,
удаление и возврат файла, пустой файл, незнакомое расширение. Полный список — в
`test/fixtures/synthetic/README.md`.

```bash
git clone test/fixtures/synthetic/history.bundle /tmp/size-report-fixture
node tools/make-fixture.js     # пересобрать фикстуру и эталон
```
